# 3단계 관리자 기능 + 모유 용량(mL) 입력 — 설계

- 날짜: 2026-11-14
- 상위 설계: `2026-11-10-모유재고관리-design.md` (10장 3단계)
- 상태: 확정·구현 완료 2026-11-15 (사용자가 질문 없이 진행을 요청함. 아래 "결정"은 모두 Claude가 정한 것이며 사용자가 바꿀 수 있다)

## 1. 목적

- 관리자가 **전체 재고 현황**과 **하루 사용량**을 앱에서 확인하고, CSV로 내보낼 수 있게 한다.
- 관리자가 **퇴원 처리**와 **개인정보 말소**(자동·즉시)를 할 수 있게 한다.
- 관리자가 알림 기준값·자동 로그아웃 시간·보관 기간을 **설정 화면**에서 바꿀 수 있게 한다.
- 사용자 요청(2026-11-14): 모유를 **mL로도 입력**할 수 있게 한다.

직원 계정 관리(추가·비활성화·비밀번호 초기화)와 환자 등록·수정, 제출처 관리는 2-2·2-3에서 이미 만들었으므로 이번에는 바꾸지 않는다.

## 2. 모유 용량(mL) — 선택 입력

### 결정 (Claude)
- mL는 **선택 입력**이다. 입력하지 않아도 지금처럼 팩 수만으로 동작한다.
- 재고·잔량·부족 판정의 단위는 **그대로 팩**이다.
- mL는 그 기록 전체의 양(총 mL)이다. 팩마다 따로 적지 않는다.
- 범위: 1~20000 mL (정수). 벗어나면 "용량은 1~20000mL 사이여야 합니다" (400).
- **남은 mL(잔량)은 보여 주지 않는다.** 사용 기록은 대개 팩 단위로만 적히므로 남은 mL를 계산하면 틀린 값이 된다. 대신 기록과 일별 통계에 입력된 mL를 보여 준다.
- 왜 이렇게 정했나: 사용자가 mL가 필요한 이유를 말하지 않았다. 팩 기준을 유지하면 지금까지 만든 재고·제출·확인 규칙과 4단계 알림 규칙을 그대로 쓸 수 있고, mL는 기록과 통계에 더해진다. 나중에 재고를 mL 기준으로 바꾸려면 이 기록이 그대로 쓰인다.

### 어디서 입력하나
| 화면 | mL 입력 |
|---|---|
| 간호사 입고·사용·폐기 창 | 팩 수 아래 "용량(mL) · 선택" 숫자 칸 |
| 보호자 "가져온 모유 입력" | 팩 수를 고른 뒤 "총 용량(mL) · 모르면 비워 두세요" 숫자 칸 |
| 간호사 수량 확인 창 | 보호자가 적은 mL가 미리 채워지고, 고치거나 지울 수 있다 |
| 퇴원 처리(남은 팩 반환·폐기) | 입력하지 않는다(빈 값) |

### 저장
- `stock_record.ml` (정수, 빈 값 허용)
- `submission.ml` (보호자가 적은 값), `submission.confirmed_ml` (간호사가 확인한 값)
- 확인으로 만들어지는 입고 기록의 ml = confirmed_ml
- 취소 기록은 대상 기록의 ml를 그대로 복사한다(통계에서 함께 빠진다).

### 보여 주기
- 기록 줄: "3팩 · 240mL" (mL가 없으면 "3팩")
- 입고 확인 대기 표: 제출 팩 수 옆에 mL (있을 때만)
- 보호자 "제출 접수 완료": "방금 제출한 모유 3팩 · 240mL"
- 결과 띠·잔량 표시는 팩만 (바꾸지 않음)

## 3. 설정

### 결정 (Claude)
서버 DB에 설정 표(`setting`, 키-값)를 새로 둔다. 값이 없으면 기본값을 쓴다.

| 키 | 이름 | 기본 | 범위 |
|---|---|---|---|
| `days_threshold` | 남은 일수 기준 | 2 | 1~30 |
| `packs_threshold` | 신규 환자 팩 수 기준 | 3 | 1~50 |
| `avg_days` | 평균 계산 기간(일) | 3 | 1~14 |
| `staff_idle_minutes` | 직원 자동 로그아웃(분) | 10 | 1~60 |
| `retention_days` | 퇴원 후 개인정보 보관(일) | 30 | 1~365 |

- 보호자 자동 로그아웃(1분)은 바꿀 수 없다(병원 공용 기기 보호 규칙).
- 기록 취소 10분 규칙, 로그인 잠금 값은 설정 화면에 넣지 않는다(서버 설정 그대로).
- `staff_idle_minutes`는 서버의 직원 세션 만료와 앱의 자동 로그아웃 둘 다에 쓴다. 앱은 로그인할 때와 홈 화면을 새로 고칠 때 이 값을 받아 쓴다.
- 환자별 기준(`days_threshold`, `packs_threshold` 환자 칸)이 있으면 그 값이 우선한다(기존 규칙).
- 푸시 발송 시간, 알림 문구는 4단계·선택 기능에서 더한다.

## 4. 전체 현황 (관리자)

### 부족 판정 (상위 설계 6장, 표시용)
이번 단계에서 판정 함수를 만들어 현황 표에 쓴다. 4단계 알림이 같은 함수를 쓴다.
- 사용 기록 일수 = 오늘(KST) − 첫 사용 기록 날짜(취소된 기록 제외)
- 사용 기록 일수 ≥ `avg_days`이면: 하루 평균 = 오늘을 뺀 최근 `avg_days`일 사용 팩 합 ÷ `avg_days`, 남은 일수 = 잔량 ÷ 하루 평균. 남은 일수 ≤ 일수 기준이면 부족. 하루 평균이 0이면 2번 기준.
- 그 밖(신규): 잔량 ≤ 팩 수 기준이면 부족.
- 잔량 0이면 항상 "없음"(빨강).
- 상태: `enough`(충분) / `low`(부족) / `empty`(0팩)

### 화면
- 요약 숫자: 입원 아기 수, 부족 아기 수(low+empty), 오늘 입고 합계(팩·mL), 오늘 사용 합계(팩·mL), 입고 확인 대기 건수
- 아기별 표: 병상, **아기 ID**, 남은 팩, 하루 평균(소수 1자리, 없으면 "—"), 남은 일수(소수 1자리, 없으면 "—"), 상태 색(🟢/🟠/🔴), 확인 대기 팩 수
  - 아기 이름은 보여 주지 않는다(화면 표시 규칙).
  - "마지막 알림" 칸은 4단계에서 더한다.
- "부족한 아기만 보기" 스위치, 정렬: 상태(기본: 없음→부족→충분, 그 안에서 남은 일수 적은 순) / 병상 / 남은 팩
- 줄을 누르면 그 아기의 재고 상세(기존 화면)로 간다.

## 5. 일별 사용량 (관리자)

- 날짜는 한국 시각(KST) 기준. 기록 시각으로 날짜를 정한다.
- **취소된 기록은 빼고** 센다(취소 기록 자체도 세지 않는다).
- 날짜 하나를 고르면: 아기별 입고·사용·폐기·퇴원 반환 팩 수와 mL 합(입력된 것만), 맨 아래 합계. 기록이 없는 아기는 표에서 뺀다.
- mL 칸 제목은 "mL(입력분)"으로, 입력된 값만 더했다는 것을 밝힌다.
- **그래프**: 최근 7일 / 30일 막대그래프. 날짜마다 사용 팩 수(막대)를 보여 주고, 위쪽 선택으로 "전체" 또는 아기 한 명을 고른다. 막대를 누르면 그날 숫자(입고·사용·폐기 팩, 사용 mL)를 보여 준다. 그래프는 외부 라이브러리 없이 앱에서 직접 그린다.
- **CSV 내보내기**: 시작일~종료일(최대 92일)을 골라 내보낸다.
  - 열: 날짜, 아기 ID, 병상, 입고 팩, 입고 mL, 사용 팩, 사용 mL, 폐기 팩, 폐기 mL, 퇴원 반환 팩
  - 하루·아기 하나가 한 줄. 기록 없는 날·아기는 줄을 만들지 않는다.
  - 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙인다.
  - 서버가 CSV를 만들고, 앱은 안드로이드 "파일로 저장" 창으로 사용자가 고른 곳에 저장한다.
- 말소된 아기는 아기 ID 자리에 "말소-{번호}"가 나온다(상위 설계 4.6 — 통계는 남는다).

## 6. 퇴원 처리 (관리자)

- 환자 수정 화면에 [퇴원 처리] 버튼.
- 남은 팩이 있으면 처리 방법을 고른다: **퇴원 반환**(보호자에게 돌려줌) / **폐기**(사유 선택).
- 확인 창: "**DEMO-03 아기**를 퇴원 처리합니다. 남은 4팩은 퇴원 반환으로 기록됩니다. 퇴원하면 입력과 보호자 로그인이 바로 막힙니다."
- 서버는 한 트랜잭션에서: 잔량이 있으면 반환/폐기 기록을 남은 팩 전부로 추가 → 상태를 퇴원으로, 퇴원일을 오늘(KST)로 → 그 아기 보호자의 로그인 세션을 끝낸다(같은 전화번호로 입원 중인 다른 아기가 없을 때).
- 확인 대기 중인 제출은 그대로 둔다. 간호사는 반려만 할 수 있다(상위 설계 8장, 기존 동작).
- 이미 퇴원한 아기를 다시 퇴원 처리하면 "이미 퇴원한 환자입니다" (409).
- **결정 (Claude): 퇴원 취소는 만들지 않는다.** 잘못 퇴원했으면 같은 등록번호로는 다시 등록할 수 없으므로(말소 전) 관리자가 확인 창에서 아기 ID를 크게 보고 확인하게 한다. 필요하면 다음 단계에서 더한다.

## 7. 개인정보 말소

상위 설계 4.6 규칙을 그대로 따른다.
- **즉시 말소**: 퇴원한 아기의 수정 화면에 [개인정보 지금 말소]. 확인 창: "되돌릴 수 없습니다. 아기 이름, 등록번호, 보호자 이름·전화번호, 기록 메모를 지웁니다." 입원 중인 아기는 말소할 수 없다(409 "퇴원한 환자만 말소할 수 있습니다").
- **자동 말소**: 서버가 켜질 때와 그 뒤 1시간마다 확인해, 퇴원일 + `retention_days`일이 지난(오늘 KST ≥ 퇴원일 + 보관일) 아직 말소되지 않은 아기를 말소한다.
- 지우는 것: 아기 이름 → "퇴원환자-{번호}", 등록번호 → "말소-{번호}", 보호자 이름 → "", 보호자 전화번호 → "", 그 아기의 재고 기록 메모와 제출 메모 → 빈 값. (번호 = 환자 번호)
- 남기는 것: 팩 수·mL·일시·입력 직원 기록.
- `patient.erased_at`에 말소 시각을 남긴다. 이미 말소된 아기는 다시 말소하지 않는다(409 "이미 말소된 환자입니다").
- 말소 후 같은 등록번호로 새로 등록할 수 있다.
- 퇴원한 아기의 환자 목록(관리자, "퇴원 포함")에서 말소된 아기는 "말소됨"으로 표시하고 수정할 수 없다.

## 8. 권한

- 전체 현황, 일별 사용량, 그래프, CSV, 설정 보기·바꾸기, 퇴원 처리, 말소: **관리자만**(서버에서 확인, 간호사는 403).
- 직원 자동 로그아웃 값(`staff_idle_minutes`)은 모든 직원이 읽을 수 있다(로그인 응답과 `/auth/me`에 포함).

## 9. 서버 API (요약 — 정확한 모양은 계획에서 정한다)

- `GET /admin/overview` — 요약과 아기별 줄
- `GET /admin/daily?date=YYYY-MM-DD` — 그날 아기별 줄과 합계
- `GET /admin/series?days=7|30[&patient_id=]` — 날짜별 합계
- `GET /admin/export.csv?from=&to=` — CSV
- `GET /admin/settings`, `PATCH /admin/settings`
- `POST /patients/{id}/discharge` — `{ "remaining": "return" | "discard", "discard_reason"?: ... }`
- `POST /patients/{id}/erase`
- 기존 API에 mL 추가: 기록 입력·기록 보기, 보호자 제출, 대기 목록, 수량 확인
- 마이그레이션 0004: `stock_record.ml`, `submission.ml`, `submission.confirmed_ml`, `patient.erased_at`, `setting` 표

## 10. 하지 않는 것 (이번 단계)

- 남은 mL 계산·표시, 팩별 mL, 유축일·유효기간
- 재고 부족 알림 만들기·소리·연락 완료 (4단계). "마지막 알림" 칸도 4단계.
- 퇴원 취소
- PDF·인쇄, 그래프 이미지 내보내기
- 직원 계정 관리 화면 변경

## 11. 테스트

- 서버(pytest): mL 범위·저장·취소 복사·확인 값, 설정 기본값·범위·권한, 부족 판정 경계값(평균 0, 신규, 기준값, 환자별 기준), 현황 요약, 일별 합계(취소 제외, KST 날짜 경계, mL 입력분만), CSV(BOM, 열, 기간 제한 92일), 퇴원(반환/폐기, 잔량 0, 이미 퇴원, 보호자 세션 종료), 말소(즉시·자동 경계, 지우는 것·남기는 것, 재등록, 이미 말소), 마이그레이션 0004 올리기·내리기

- 앱(화면 테스트): 관리자 현황 → 일별 사용량 흐름 하나
- 에뮬레이터로 끝까지 확인: mL를 넣어 제출·확인 → 일별 사용량에 mL 합계 → CSV 저장 → 퇴원 → 즉시 말소
