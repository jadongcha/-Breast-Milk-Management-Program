## 1. 목표와 범위

2-2가 끝나면 **병원 기기의 앱만으로 시범 사용을 할 수 있어야 한다**. 환자 등록, 직원 계정 관리, 입고·사용·폐기, 잔량 확인이 모두 앱에서 된다.

### 포함
- 서버 등록 QR 스캔과 인증서 고정(공개키 지문 확인) HTTPS 연결
- 직원 로그인, 처음 로그인할 때 비밀번호 변경, 로그아웃, 10분 자동 로그아웃, 연결 끊김 표시
- 환자 목록·검색·상세, 입고·사용·폐기와 확인 창, 기록 취소
- **간단한 관리자 화면**: 환자 등록·수정, 직원 목록·추가·비활성화·비밀번호 초기화
- 태블릿 2단 / 휴대폰 1단 화면
- 화면 예시를 따른 디자인과 **아기 ID 표시**(3.4, 3.5, 3.8)
- 서버 보강 1건: 기록 응답에 입력 직원 번호(`staff_id`) 추가 (5장)

### 3단계 이후로 남기는 것
- 전체 현황·일별 통계·CSV, 퇴원 처리, 개인정보 말소, 설정 화면 → 3단계
- 재고 부족 판정과 알림, "보호자 연락 필요" 목록, 주황색 "부족" 표시 → 4단계
- 보호자 화면(제출처 태블릿), 보호자 제출, 간호사 입고 확인 대기·수량 확인 → 2-3단계. 2-2의 홈에는 "입고 확인 대기" 자리만 두고 "확인할 제출이 없습니다"를 보여 준다
- 정식 배포용 APK 서명 키 → 7단계 (2-2는 개발용 APK)

## 2. 기술 구성

| 항목 | 결정 |
|---|---|
| 언어·화면 | Kotlin, Jetpack Compose (Material 3), 액티비티 1개 + Navigation Compose |
| 최소/대상 안드로이드 | minSdk 26 (안드로이드 8), compileSdk·targetSdk 37 |
| 구조 | 화면마다 ViewModel + StateFlow. 서버 호출은 저장소(Repository) 계층을 거친다 |
| 통신 | OkHttp + Retrofit + kotlinx.serialization |
| 인증서 확인 | QR의 `pin`(공개키 SHA-256 지문)과 서버 인증서의 공개키를 비교하는 자체 `X509TrustManager`. 일치하지 않으면 연결을 끊는다. 호스트 이름 확인은 지문 확인으로 대신한다 |
| QR 스캔 | CameraX + ML Kit 바코드 스캔(앱에 내장된 모델, 인터넷 불필요) |
| 기기 저장 | DataStore에 서버 주소(`url`)와 지문(`pin`)만 저장. **로그인 토큰은 메모리에만** 둔다 |
| 권한 | 카메라(서버 등록 QR), **근처 기기(로컬 네트워크) — Android 17 이상에서 필수**. 이 권한이 없으면 앱이 병원 내부망(사설 IP) 서버에 아예 연결할 수 없다. 처음 실행할 때 요청하고, 거부하면 "병원 서버에 연결하려면 '근처 기기(로컬 네트워크)' 권한이 필요합니다"와 [권한 다시 요청]/[설정에서 권한 허용]을 보여 준다 |
| 위치 | 저장소 루트의 `android/` 폴더, Gradle Kotlin DSL, 패키지 `app.milkbank` |
| 빌드 | Gradle wrapper. 처음 빌드할 때 라이브러리를 인터넷에서 내려받는다 |

## 3. 화면

### 3.1 서버 등록
- 앱을 처음 켜면(저장된 서버가 없으면) 이 화면이 나온다. 카메라 권한에 이어 근처 기기(로컬 네트워크) 권한을 요청한다(Android 17 이상).
- 개발용 앱에만 **[테스트용 서버로 등록 (개발용)]** 버튼이 보인다. 기기의 앱 전용 폴더에 넣은 `qr.txt`(QR 내용)를 읽어 QR을 찍은 것과 똑같이 확인·등록한다. 정식 앱에는 없다. "신생아실에 보관된 서버 등록 QR을 찍어 주세요"
- 카메라 권한을 요청할 때 이유를 안내한다. 권한을 거부하면 다시 요청하는 버튼과 안내 문구를 보여 준다.
- QR 내용이 `{"type":"milkbank-server","v":1,"url":...,"pin":"sha256/..."}` 형식이 아니면 "서버 등록 QR이 아닙니다"
- 형식이 맞으면 그 주소와 지문으로 `GET /health`를 시도한다.
  - 성공하면 저장하고 로그인 화면으로 간다.
  - 실패하면 "서버에 연결할 수 없습니다. 병원 와이파이에 연결되어 있는지 확인해 주세요"
- **다시 등록**: 로그인 화면 메뉴의 "서버 다시 등록"
  - 새 QR의 `pin`이 저장된 값과 같으면 주소만 바뀐 것으로 보고 바로 반영한다.
  - **다르면** 경고 창을 띄운다: "다른 서버로 바꿉니다. 병원 전산 담당자가 안내한 경우에만 계속하세요" → [취소]/[바꾸기]

### 3.2 로그인
- 아이디, 비밀번호, [로그인]. 실패하면 서버의 `detail` 문구를 그대로 보여 준다(잠김 429 포함).
- 로그인 응답의 `must_change_password`가 참이면 비밀번호 변경 화면으로 간다.

### 3.3 비밀번호 변경
- 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인
- 새 비밀번호와 확인이 다르면 "새 비밀번호가 서로 다릅니다"(앱에서 확인). 나머지 규칙은 서버 문구를 그대로 보여 준다.
- 성공하면 홈으로 간다. 처음 로그인이 아니어도 메뉴에서 바꿀 수 있다.

### 3.4 홈 = 입고 확인 및 재고 관리 (화면 예시 기준)
- 위쪽 막대: 제목 "입고 확인 및 재고 관리", 로그인한 직원 이름, 메뉴(비밀번호 변경, 관리자 메뉴, 로그아웃)
- **결과 띠**: 방금 저장한 결과를 한 줄로 보여 준다. 예: "DEMO-01 · 3팩 입고 완료 · 현재 냉동 재고 8팩". 다음 저장 전까지 유지
- **입고 확인 대기** 카드: 2-2에서는 "확인할 제출이 없습니다"만 표시(2-3에서 표가 들어감). [대기 목록 접기/펼치기]
- **전체 재원 아기 보기 · N명** 펼치기 단추: 펼치면 목록. 각 줄 `아기 ID | 남은 N팩`, 0팩은 빨간색. 순서는 서버가 정한 병상순
- **아기 ID 검색**: 입력칸 + [{아기 ID} · 선택] 버튼. 입력과 정확히 같거나 부분 일치하는 아기가 하나면 버튼에 그 ID가 표시되고, 누르면 상세가 열린다. 여러 명이면 목록을 걸러 보여 준다
- 아래로 당기면 새로고침된다. 저장하고 돌아오면 자동으로 새로고침된다

### 3.5 환자 상세 = "{아기 ID} 모유 재고 상세"
- 위쪽: **아기 ID(크게)**, 병상, 보호자 이름·전화번호(직원 연락용). 아기 이름은 보이지 않는다
- 가운데 카드: "확정 냉동 재고" **N팩**(아주 크게)
- 큰 버튼 세 개
  - **[입고]**: 숫자 버튼 1~10 + 메모(선택)
  - **[사용]**: 기본 1팩, +/− (1~10)
  - **[폐기]**: 팩 수 + 사유(해동 후 남음 / 오염 / 기타) + 메모
- **확인 창**: "**{아기 ID} 아기**에게 **{N}팩 {입고/사용/폐기}**하시겠습니까?" — 아기 ID를 크게. [취소]/[확인]
- 저장에 성공하면 잔량과 기록이 바로 바뀌고 "저장했습니다"가 잠깐 표시되며, 홈의 결과 띠도 바뀐다. 실패하면 서버 문구(예: "재고가 부족합니다 (현재 0팩)")를 보여 준다.
- 최근 기록(최신순): 일시(한국 시각), 종류, 팩 수, 입력 직원, 메모. 취소된 기록은 흐리게 하고 "취소됨"을 붙인다.
  - **[취소] 버튼**은 다음 기록에만 보인다.
    - 관리자: 취소 기록이 아니고 아직 취소되지 않은 모든 기록
    - 간호사: 위 조건에 더해, `staff_id`가 본인이고 입력 후 10분이 지나지 않은 기록
  - 누르면 확인 창("이 기록을 취소하시겠습니까?")을 띄운다. 최종 판단은 서버가 한다.

### 3.6 관리자 메뉴 (역할이 관리자일 때만 보임)
- **환자 등록·수정**
  - 칸: 등록번호, 아기 이름, 병상, 보호자 이름, 보호자 전화번호, 입원일(기본 오늘)
  - 알림 관련 칸은 4단계에서 보인다.
  - 수정은 환자 상세의 [수정] 버튼으로 연다.
  - 아기 이름은 이 화면에서만 보인다. 등록번호 칸의 이름은 "아기 ID(등록번호)"
- **직원 관리**
  - 목록: 아이디, 이름, 역할, 활성 여부
  - [직원 추가]: 아이디, 이름, 역할(간호사/관리자) → 성공하면 **임시 비밀번호를 크게 한 번 보여 준다**("이 비밀번호를 직원에게 전달하세요. 다시 볼 수 없습니다")
  - [비활성화]/[활성화], [비밀번호 초기화](새 임시 비밀번호를 같은 방식으로 표시). 모두 확인 창을 거친다.

### 3.7 화면 배치
- 화면 너비가 넓으면(태블릿 가로, 840dp 이상) 왼쪽 환자 목록 + 오른쪽 상세의 2단으로 보여 준다.
- 좁으면 목록과 상세를 한 화면씩 넘긴다.
- 글자와 버튼은 장갑을 낀 손으로도 누를 수 있게 크게 만든다(버튼 높이 최소 56dp).


### 3.8 디자인 (화면 예시 기준)
- 색: 기본 진한 청록 `#11695C`(버튼·강조 숫자), 연한 청록 `#E2F1ED`(결과 띠·카드 배경), 화면 배경 `#F4F8F7`, 카드 흰색, 테두리 `#D5E2DE`, 글자 `#1D2A2E`, 보조 글자 `#5B6B70`, 0팩·오류 빨강 `#C0392B`, 건수 배지 노랑 `#FCEBC7`
- 카드: 둥근 모서리 12dp, 얇은 테두리, 그림자 없음. 큰 숫자는 굵게(재고 숫자 48sp 이상)
- 버튼: 진한 청록 바탕 흰 글자(주 버튼), 연한 회색 바탕(보조 버튼), 높이 최소 56dp
- 글꼴: 시스템 기본(한글). 제목 굵게

## 4. 동작 규칙

- **자동 로그아웃**
  - 마지막 터치 후 10분이 지나면 토큰을 지우고 로그인 화면으로 간다(서버 규칙과 같은 시간).
  - 서버가 401을 주면 언제든 토큰을 지우고 로그인 화면으로 가서 "다시 로그인해 주세요"를 보여 준다.
  - 앱이 백그라운드로 갔다가 돌아왔을 때도 10분이 지났으면 같은 처리를 한다.
- **연결 확인**
  - 앱이 화면에 보이는 동안 30초마다 `GET /health`를 보낸다(로그인 세션을 연장하지 않는다).
  - 실패하면 위쪽에 빨간 "서버 연결 안 됨" 띠를 띄우고 입고·사용·폐기·취소·관리자 저장 버튼을 막는다.
  - 다시 성공하면 띠를 내린다.
- **중복 저장 방지**: 요청을 보내는 중에는 같은 버튼을 막는다.
- **오류 표시**: 서버 응답의 `detail`이 있으면 그 문구를 보여 준다. 없으면(네트워크 오류 등) "서버에 연결할 수 없습니다"
- **403 "비밀번호를 먼저 변경해야 합니다"**: 비밀번호 변경 화면으로 보낸다.
- 시각은 서버의 UTC 값을 기기에서 한국 시각으로 바꿔 보여 준다.

## 5. 서버 보강 (2-2에 포함)

- `RecordOut`에 `staff_id: int`를 추가한다(입력 직원 번호). 이름이 같은 직원이 있어도 앱이 "본인 기록"을 정확히 판단하게 하기 위해서다. DB 구조는 바뀌지 않으므로 마이그레이션은 필요 없다.
- 서버 테스트에 이 값을 확인하는 항목을 추가한다.

## 6. 테스트

- **단위 테스트(JVM)**
  - 아기 ID 검색(정확히 일치, 부분 일치 하나/여러 개, 없음)
  - 공개키 지문 확인: 맞는 인증서는 통과, 다른 키의 인증서는 거부
  - QR 내용 해석: 정상, 형식 오류, type/v 다름
  - 서버 재등록 규칙: pin 같음 → 바로 반영, 다름 → 경고 필요
  - 취소 버튼 표시 규칙(관리자/간호사, 10분 경계, 취소 기록, 이미 취소됨)
  - ViewModel 상태: 가짜 저장소로 로그인 성공·실패·비밀번호 변경 필요, 입고 성공·실패, 401 → 로그아웃
  - 자동 로그아웃 타이머(가짜 시계)
- **화면 테스트(에뮬레이터)**: 로그인 → 목록 → 상세 → 입고 → 확인 창 → 잔량 반영. 가짜 저장소를 쓴다.
- **실제 연결 확인**: 이 PC에서 `milkbank-setup-tls --host 10.0.2.2`와 `milkbank-serve`를 실행하고, 에뮬레이터에서 QR(이미지 파일)로 등록한 뒤 끝까지 사용해 본다. QR 스캔은 에뮬레이터 가상 카메라나 수동 입력용 디버그 메뉴로 확인한다.
- 실제 갤럭시 기기 확인은 기기를 USB로 연결할 수 있을 때 한다.

## 7. 알아 둘 점

- 첫 빌드 때 Gradle이 Google Maven과 Maven Central에서 라이브러리를 내려받는다.
- 개발용 APK는 Android Studio의 디버그 키로 서명된다. 병원 기기에 설치하는 정식 APK의 서명 키는 7단계에서 만들고 안전하게 보관한다.
