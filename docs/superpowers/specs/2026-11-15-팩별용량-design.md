# 팩별 용량(mL)과 남은 용량 표시 — 설계

- 날짜: 2026-11-15
- 상위 설계: `2026-11-10-모유재고관리-design.md`, 직전 단계 `2026-11-14-3단계-관리자기능-design.md`(2장 mL 선택 입력을 이 설계가 바꾼다)
- 상태: 사용자 승인 대기 (만들기 전 검토 반영)

## 1. 목적과 이유

- 사용자 요청(2026-11-15): "재고 확인할 때 mL를 확인할 수 있게". 팩은 **팩마다 용량이 정해져 있다**(사용자 답).
- 3단계에서는 기록마다 총 mL만 선택 입력해서, 사용 기록에 mL가 비어 남은 mL를 계산할 수 없었다.
- 이번에는 **팩 하나하나를 재고로 관리**해 남은 mL를 정확히 보여 준다. 사용자가 세 방법(팩마다 저장 / 입고 묶음 평균 / 병원 기준 한 팩 용량) 가운데 **팩마다 저장**을 골랐다.

## 2. 목표 · 하지 않는 것

**목표**
- 재고를 보는 모든 곳에서 "4팩 · 340mL"처럼 남은 팩과 남은 mL를 함께 보여 준다.
- 입고(간호사 직접, 보호자 제출 → 간호사 확인)에서 팩마다 mL를 적을 수 있다. 모르면 비워 둔다.
- 사용·폐기는 지금처럼 팩 수만 고르면 된다(가장 오래 들어온 팩부터 자동). 원하면 남은 팩 목록에서 직접 고른다.

**하지 않는 것**
- 유축일·유효기간, 팩 라벨 번호·바코드
- 팩의 일부만 쓰기(반 팩 사용). 팩은 통째로 나간다.
- 부족 판정을 mL 기준으로 바꾸기. 판정은 계속 팩 기준(4단계도 팩 기준).

**피해야 할 것(실패로 본다)**
- 남은 mL가 실제와 다르게 보이는 것. 용량을 모르는 팩이 섞이면 숫자를 지어내지 않고 "용량 모름 N팩"으로 따로 보인다.
- 간호사의 사용 입력이 지금보다 느려지는 것(버튼 한 번 그대로).

## 3. 결정

### 3.1 팩 단위 재고 (사용자 결정)
- 서버에 **팩 표(`pack`)**를 둔다: 번호, 환자, 용량 mL(빈 값 허용), 들어온 입고 기록, 나간 기록(빈 값 = 재고에 있음), 만든 시각.
- 입고 기록 1건(N팩)은 팩 N개를 만든다. 사용·폐기·퇴원 반환 기록 1건(N팩)은 재고에 있는 팩 N개를 내보낸다.
- **잔량 = 재고에 있는 팩 수**. 기존 계산(입고 − 사용 − 폐기 − 반환, 취소 제외)과 항상 같아야 한다(테스트로 확인).
- **남은 mL = 재고에 있는 팩 중 용량을 아는 팩의 mL 합**, **용량 모름 = 재고에 있는데 mL가 빈 팩 수**.

### 3.2 팩 용량 범위 (Claude)
- 팩 하나 1~1000 mL 정수. 벗어나면 "팩 용량은 1~1000mL 사이여야 합니다"(400).

### 3.3 어느 팩이 나가나 (Claude)
- 사용·폐기에서 팩을 고르지 않으면 **가장 먼저 들어온 팩부터**(입고 시각, 같으면 팩 번호 순) 나간다.
- 고를 수도 있다: 남은 팩 목록에서 팩 수만큼 고른다. 고른 팩이 그 아기 재고에 없거나 수가 맞지 않으면 "고른 팩을 다시 확인해 주세요"(409).
- 퇴원 처리는 남은 팩 전부를 내보낸다.

### 3.4 기록의 mL (3단계 값과의 관계, Claude)
- 기록의 `ml`은 이제 **입력하지 않고, 기록을 쓸 때 팩에서 계산해 저장**한다: 그 기록으로 들어오거나 나간 팩 중 용량을 아는 팩의 합(하나도 모르면 빈 값). 함께 **용량 모름 팩 수**(`ml_unknown`)를 저장한다. 읽을 때 다시 계산하지 않으므로 3단계에 적힌 옛 기록의 `ml`은 바뀌지 않는다(옛 기록의 `ml_unknown`은 0).
- 기록 줄: 모두 알면 "3팩 · 240mL", 일부 모르면 "3팩 · 160mL (용량 모름 1팩)", 모두 모르면 "3팩".
- 일별 사용량·CSV의 mL 칸은 지금처럼 "입력분"(아는 값의 합)이다. 제목이 이미 "mL(입력분)"이라 모르는 팩이 빠진 값임을 밝힌다.
- 기록 입력 API의 `ml`은 더 이상 받지 않는다(무시). 입고는 `pack_mls`(팩 수만큼, 칸마다 빈 값 허용), 사용·폐기는 `pack_ids`(선택)를 받는다. `pack_mls` 길이가 팩 수와 다르면 "팩마다 용량 칸 수가 맞지 않습니다"(400).
- 취소 기록은 대상 기록의 `ml`과 `ml_unknown`을 복사한다.

### 3.5 취소 (Claude)
- 사용·폐기 기록을 취소하면 그 기록으로 나간 팩이 재고로 돌아온다.
- 입고 기록을 취소하면 그 입고로 들어온 팩이 **모두 재고에 있을 때만** 취소된다(팩이 사라진다). 하나라도 나갔으면 "이 입고의 팩이 이미 사용되었습니다. 사용 기록을 먼저 취소해 주세요"(409). 기존 규칙(잔량이 음수가 되면 막음)보다 엄격하지만, 어느 팩이 나갔는지가 기록되므로 맞는 규칙이다.
- 퇴원 반환·폐기 기록은 지금처럼 취소할 수 없다(퇴원한 환자 입력 금지 규칙).

### 3.6 보호자 제출과 간호사 확인 (Claude)
- 보호자: 팩 수(1~10)를 고르면 팩 수만큼 "팩 1 mL, 팩 2 mL …" 칸이 나온다(모르면 비움). 위에 "모두 같은 용량" 칸이 있어 하나만 적으면 전부 채운다. 3단계의 "총 용량" 칸은 없어진다.
- 제출 기록에 팩별 용량 목록(`pack_mls`, 칸마다 빈 값 허용)을 저장한다. `submission.ml`은 그 합(계산값)으로 둔다.
- 간호사 수량 확인: 보호자가 적은 목록이 칸마다 채워져 있다. 팩 수를 바꾸면 칸이 늘거나 줄고(늘어난 칸은 빈 값), 칸마다 고칠 수 있다. 확인 요청에 `pack_mls`가 아예 없으면 보호자 목록을 팩 수에 맞춰 자르거나 빈 칸을 더해 쓴다(3단계 규칙과 같은 방식). 명시하면 그 값.

### 3.7 기존 자료 옮기기 (Claude)
- 마이그레이션 0005가 지금 재고를 팩으로 만든다: 아기마다 취소되지 않은 기록을 시각 순으로 따라가며 입고는 팩 N개를 만들고(용량은 그 입고의 mL가 팩 수로 **나누어떨어질 때만** 팩마다 그 값, 아니면 빈 값), 사용·폐기·반환은 가장 먼저 들어온 팩부터 내보낸다.
- 옮긴 뒤 아기마다 재고에 있는 팩 수가 기존 잔량과 같은지 확인하고, 다르면 마이그레이션을 멈춘다(되돌림).
- 3단계에서 이미 적힌 기록의 `ml` 값은 그대로 둔다(통계 유지).
- 마이그레이션 때 **확인 대기 중인 보호자 제출**은 `pack_mls`를 채운다: 3단계 총 mL가 팩 수로 나누어떨어지면 팩마다 그 값, 아니면(또는 mL가 없으면) 모두 빈 값. 처리가 끝난 제출은 건드리지 않는다.

### 3.8 보여 주기
| 화면 | 표시 |
|---|---|
| 간호사 재고 상세 | "확정 냉동 재고 4팩 · 340mL"(모르는 팩이 있으면 "· 용량 모름 1팩"), 그 아래 **남은 팩** 목록(들어온 날짜, mL 또는 "모름") |
| 간호사 아기 목록 줄 | 남은 팩 옆에 mL |
| 관리자 전체 현황 | 남은 팩 칸에 mL, 요약은 그대로 |
| 보호자 화면 | "현재 확인된 냉동 모유 4팩 · 340mL" |
| 결과 띠 | "현재 냉동 재고 4팩 · 340mL" |
| 사용·폐기 창 | 팩 수 버튼(지금 그대로) + 나갈 팩 미리 보기("80mL, 80mL") + [팩 고르기] |

- 아기 이름은 지금처럼 보이지 않는다.

## 4. 서버 API 변화 (요약 — 정확한 모양은 계획에서)

- `POST /patients/{id}/records`: 입고 `pack_mls`, 사용·폐기 `pack_ids`(선택). `ml` 무시.
- `GET /patients/{id}`: `balance_ml`, `unknown_ml_packs`, `packs`(재고에 있는 팩: id, ml, 들어온 시각)
- `GET /patients`: `balance_ml`, `unknown_ml_packs`
- 보호자 `GET /guardian/babies`, 로그인 응답, 제출 응답: `balance_ml`, `unknown_ml_packs`; 제출 `pack_mls`
- 대기 목록: `pack_mls`; 확인 `pack_mls`(없으면 보호자 값)
- `GET /admin/overview` 줄: `balance_ml`, `unknown_ml_packs`
- 기록 결과(`RecordResult`, 확인 결과): `balance_ml`, `unknown_ml_packs`

## 5. 안전·개인정보

- 팩 표에는 개인정보가 없다(용량과 시각뿐). 말소 때 지우지 않는다.
- 모든 쓰기는 기존처럼 BEGIN IMMEDIATE 한 트랜잭션: 팩 고르기와 기록 추가가 같이 이뤄져 두 기기가 같은 팩을 동시에 내보낼 수 없다.

## 6. 테스트

- 서버: 잔량 = 재고 팩 수(모든 기록 종류·취소 조합), 먼저 들어온 팩부터, 팩 고르기(남의 팩·이미 나간 팩·수 불일치), 입고 취소 규칙, 사용 취소로 팩 복귀, 기록 ml 계산값, 남은 mL와 용량 모름, 보호자 목록 → 확인(생략/명시/팩 수 변경), 퇴원 시 전부 내보내기, 마이그레이션 0005(나누어떨어짐/아님, 잔량 일치 확인, 되돌리기)
- 앱: 팩별 칸과 "모두 같은 용량", 칸 수 맞추기, 남은 팩 목록, 팩 고르기, 표시 문구
- 에뮬레이터로 끝까지: 보호자 3팩(80/80/100) 제출 → 간호사 확인 → 재고 "3팩 · 260mL" → 사용 1팩(80mL가 나감) → "2팩 · 180mL" → 팩 골라 폐기 → 일별 사용량 mL

- **앱 계획**: 팩별 입력 칸, 남은 팩 목록·팩 고르기, 표시 문구, 끝까지 확인
