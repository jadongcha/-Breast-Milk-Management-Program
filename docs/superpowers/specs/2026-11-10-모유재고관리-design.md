# 신생아실 모유 재고관리 앱 — 설계 문서

- 작성일: 2026-11-10
- 상태: 검토 대기

---

## 1. 목적

신생아 환자(약 59명)의 보호자가 유축해 얼려 오는 모유(한 번에 2~5팩)를 병원이 **팩 개수 단위**로 관리한다.

- 간호사는 입고·사용·폐기를 빠르고 정확하게 기록한다.
- 관리자는 환자별 재고 현황과 일별 사용량을 본다.
- 재고가 거의 떨어지면 서버가 보호자에게 **자동으로 문자/알림톡**을 보낸다.
- 보호자는 병원 와이파이에서 자기 아기의 재고를 조회한다.

### 성공 기준
- 종이 장부 없이 앱만으로 59명의 모유 재고를 관리할 수 있다.
- 여러 기기(갤럭시탭, 갤럭시폰)에서 동시에 입력해도 잔량이 항상 일치한다.
- 재고 부족 보호자에게 사람이 직접 연락하지 않아도 알림이 간다(같은 부족 상황에 중복 발송 없음).
- 다른 아기의 모유를 잘못 기록하는 실수를 확인 창으로 막는다.

## 2. 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 사용 기기 | 안드로이드 (갤럭시탭, 갤럭시폰) |
| 데이터 공유 | 여러 기기 공유, **병원 내부망 서버** (외부 클라우드 사용 안 함) |
| 개발 방식 | 안드로이드 네이티브 앱 + 내부 서버 |
| 재고 단위 | **팩 개수만** (ml, 유축일, 유효기간 관리 안 함) |
| 환자 선택 | 목록에서 검색·선택 (바코드/QR 스캔 없음) |
| 보호자 알림 | 서버가 문자/알림톡 **자동 발송** |
| 알림 기준 | 남은 일수 기준(기본) + 사용 기록이 부족한 신규 환자는 남은 팩 수 기준 |
| 계정 | 직원(관리자/간호사) + 보호자 |
| 직원 로그인 | 아이디 + **본인이 직접 설정한 비밀번호** |
| 보호자 로그인 | 전화번호 + 아기 등록번호 |
| 보호자 접속 범위 | **병원 와이파이에서만** (병원 밖 조회 안 함) |

## 3. 시스템 구성

```
[갤럭시탭 / 갤럭시폰 앱]  ──병원 와이파이(HTTPS)──▶  [내부 서버]  ──외부 연결(방화벽 허용)──▶  [문자/알림톡 업체]  ──▶  보호자 휴대폰
  직원·보호자 공용 앱                                  API 서버 + DB
```

### 기술 구성
- **앱**: Kotlin + Jetpack Compose. 직원과 보호자가 같은 앱을 쓰고 로그인 화면에서 [직원]/[보호자] 탭을 고른다.
- **서버**: Python FastAPI + PostgreSQL. 병원 내부 서버 1대에 설치한다.
- **알림**: 서버가 문자/알림톡 업체 API를 호출한다. 업체 연동 부분은 교체할 수 있게 분리한다.
- **통신 보안**: 보호자 휴대폰과 직원 기기가 같은 와이파이를 쓰므로 비밀번호가 평문으로 오가면 안 된다. 서버는 자체 서명 인증서로 HTTPS를 쓰고, 앱에 그 인증서를 내장(인증서 고정)한다. 따라서 공인 인증서는 필요 없다.

### 앱 배포
- Play 스토어를 쓰지 않는다. 내부 서버의 다운로드 페이지에서 APK를 받는다.
- 보호자는 병원 와이파이에 연결한 뒤 신생아실에 붙인 QR코드로 다운로드 페이지에 접속한다. 휴대폰에서 "출처를 알 수 없는 앱 설치"를 허용해야 한다.
- 다운로드 페이지는 브라우저에서 자체 서명 인증서 경고가 뜨지 않도록 HTTP로 제공한다. 이 페이지는 APK 파일만 내려주고 개인정보는 다루지 않는다. 앱과 서버 사이의 통신은 모두 HTTPS를 쓴다.
- 앱 업데이트도 같은 방식이다. 앱은 실행할 때 서버에 최신 버전을 물어보고, 새 버전이 있으면 설치를 안내한다.

## 4. 데이터

### 4.1 환자 (patient)
| 필드 | 설명 |
|---|---|
| 등록번호 | 병원 환자번호. 중복 불가. 보호자 로그인에 쓰인다 |
| 아기 이름 | |
| 병상 | |
| 보호자 이름 | |
| 보호자 전화번호 | 알림 수신과 보호자 로그인에 쓰인다 |
| 상태 | 입원 / 퇴원 |
| 입원일, 퇴원일 | |
| 알림 사용 여부 | 기본값: 사용 |
| 개별 남은 일수 기준 | 비어 있으면 전체 설정을 따른다 |
| 개별 팩 수 기준 | 비어 있으면 전체 설정을 따른다 |
| 알림 상태 | 정상 / 부족 알림 보냄 (중복 발송 방지용) |

### 4.2 재고 기록 (stock_record)
기록은 수정하거나 삭제하지 않고 추가만 한다. 잘못 입력한 기록은 "취소" 기록으로 바로잡는다.

| 필드 | 설명 |
|---|---|
| 환자 | |
| 종류 | 입고 / 사용 / 폐기 / 퇴원 반환 / 취소 |
| 팩 수 | 1 이상 |
| 폐기 사유 | 해동 후 남음 / 오염 / 기타 (폐기일 때만) |
| 취소 대상 | 취소한 기록의 번호 (취소일 때만) |
| 일시 | 서버 시각 |
| 입력 직원 | |
| 메모 | 선택 |

**현재 잔량** = 입고 − 사용 − 폐기 − 퇴원 반환. 취소된 기록은 계산에서 뺀다. 잔량 계산은 서버에서만 한다.

### 4.3 알림 기록 (notification)
환자, 받는 번호, 문구, 만든 시각, 보낸 시각, 결과(대기 / 성공 / 실패), 실패 사유.

### 4.4 직원 계정 (staff)
아이디(중복 불가), 이름, 역할(관리자 / 간호사), 비밀번호 해시(argon2), 임시 비밀번호 여부, 활성 여부.

### 4.5 설정 (settings)
| 항목 | 기본값 |
|---|---|
| 남은 일수 기준 | 2일 |
| 신규 환자 팩 수 기준 | 3팩 |
| 평균 계산 기간 | 최근 3일 |
| 발송 가능 시간 | 08:00 ~ 21:00 |
| 직원 자동 로그아웃 | 아무 조작 없이 10분 |
| 알림 문구 | "[OO병원 신생아실] {아기이름} 아기의 모유가 약 {남은일수}일분({남은팩}팩) 남았습니다. 방문 시 모유를 가져와 주세요." |

## 5. 계정과 권한

| 기능 | 관리자 | 간호사 | 보호자 |
|---|:-:|:-:|:-:|
| 환자 목록·상세 조회 | ✅ | ✅ | 자기 아기만 |
| 입고 / 사용 / 폐기 | ✅ | ✅ | ❌ |
| 기록 취소 | 언제든 | 본인 기록, 10분 이내 | ❌ |
| 전체 현황, 일별 사용량, CSV | ✅ | ❌ | ❌ |
| 환자 등록·수정·퇴원 | ✅ | ❌ | ❌ |
| 알림 관리 | ✅ | ❌ | ❌ |
| 설정, 직원 계정 관리 | ✅ | ❌ | ❌ |

권한은 **서버에서** 확인한다. 앱이 버튼을 숨기는 것만으로는 막지 않는다.

### 직원 로그인
- 관리자가 계정을 만들면 임시 비밀번호가 발급된다.
- 처음 로그인할 때 새 비밀번호를 반드시 직접 설정해야 한다. 설정하기 전에는 다른 기능을 쓸 수 없다.
- 비밀번호는 8자 이상이고 영문과 숫자를 섞어야 한다.
- 비밀번호를 잊으면 관리자가 초기화하고, 다시 임시 비밀번호부터 시작한다.
- 10분 동안 아무 조작이 없으면 자동으로 로그아웃된다 (공용 태블릿 대비).

### 보호자 로그인
- 따로 가입하지 않는다. 직원이 환자를 등록할 때 입력한 **보호자 전화번호 + 아기 등록번호**가 일치하고 아기가 입원 중이면 로그인된다.
- 로그인한 뒤에는 같은 전화번호로 등록된 입원 중인 아기를 모두 보여 준다 (쌍둥이 등).
- 같은 전화번호로 로그인을 5번 연속 실패하면 10분 동안 잠긴다.
- 아기가 퇴원하면 로그인할 수 없다.

## 6. 재고 부족 알림 규칙

### 판정
1. **사용 기록이 3일 이상인 환자** (첫 사용 기록일로부터 3일 이상 지남)
   - 하루 평균 = 오늘을 뺀 최근 3일 동안의 사용 팩 수 ÷ 3
   - 남은 일수 = 현재 잔량 ÷ 하루 평균
   - **남은 일수 ≤ 2일**이면 부족으로 본다.
   - 하루 평균이 0이면 남은 일수를 계산하지 않고 아래 2번 기준을 쓴다.
2. **신규 환자** (사용 기록 3일 미만): **남은 팩 ≤ 3팩**이면 부족으로 본다.
3. 잔량이 0이면 항상 부족이다.

기준값은 설정에서 바꿀 수 있고, 환자별로 따로 정할 수도 있다.

### 판정 시점
- 재고 기록이 생기거나 취소될 때마다 판정한다.
- 평균 계산 기간이 날마다 바뀌므로 매일 08:00에 전체 환자를 다시 판정한다.

### 발송
- 알림 상태가 **정상 → 부족**으로 바뀔 때 **한 번만** 보낸다.
- 입고로 기준 위로 올라가면 알림 상태가 정상으로 돌아가서, 다음에 다시 부족해질 때 또 보낼 수 있다.
- 발송 가능 시간(08:00~21:00)이 아니면 대기시켰다가 다음 08:00에 보낸다. 그때까지 입고되어 부족 상황이 풀렸으면 보내지 않는다.
- 알림 사용을 끈 환자와 퇴원한 환자에게는 보내지 않는다.
- 발송이 실패하면 관리자 화면에 "알림 실패"로 표시하고, 관리자가 다시 보낼 수 있다.

### 상태 색상 (목록 화면)
- 🟢 충분 / 🟠 부족 / 🔴 잔량 0팩

## 7. 화면

태블릿에서는 목록과 상세를 2단으로 나란히 보여 준다(왼쪽 목록, 오른쪽 상세). 휴대폰에서는 한 화면씩 넘겨 본다.

### 공통
- **로그인**: [직원] / [보호자] 탭
- **최초 비밀번호 설정** (직원)

### 간호사
- **환자 목록 (홈)**: 이름·병상·등록번호로 검색한다. 각 줄에 `병상 | 아기 이름 | 남은 팩 | 약 N일분 | 상태`를 보여 주고, 부족한 환자를 맨 위에 둔다.
- **환자 상세**
  - 큰 글씨로 남은 팩 수와 약 며칠분인지 보여 준다.
  - 큰 버튼: **[입고]** (숫자 버튼 1~10 + 메모), **[사용]** (기본 1팩, +/−), **[폐기]** (팩 수 + 사유)
  - **확인 창**: "**3번 병상 김OO 아기**에게 **3팩 입고**하시겠습니까?" — 아기 이름과 병상을 크게 보여 준다.
  - 최근 기록(일시, 종류, 팩 수, 입력 직원), 보호자 연락처, 알림 기록
  - 기록 취소 (권한 규칙은 5장을 따른다)

### 관리자 (간호사 화면 포함)
- **전체 현황**: 요약 숫자(입원 환자 수, 부족 환자 수, 오늘 입고/사용 합계)와 환자별 표(병상, 이름, 남은 팩, 하루 평균, 남은 일수, 상태, 마지막 알림). "부족한 환자만 보기" 필터와 정렬을 지원한다.
- **일별 사용량**: 날짜를 고르면 환자별 입고·사용·폐기 팩 수와 합계를 보여 준다. 최근 7일/30일 막대그래프(전체 합계와 환자별), CSV 내보내기.
- **환자 관리**: 등록, 수정, 환자별 알림 기준·알림 사용 여부 설정, **퇴원 처리** (남은 팩을 반환 또는 폐기로 기록한 뒤 퇴원 상태로 바꾼다. 기록은 보존한다)
- **알림 관리**: 발송 기록, 실패 목록, 다시 보내기, 문구 편집
- **설정·직원 관리**: 알림 기준값, 발송 가능 시간, 자동 로그아웃 시간, 직원 계정 추가·비활성화·비밀번호 초기화

### 보호자 (조회만 가능)
- 아기 선택 (여러 명일 때)
- 남은 팩 수, 약 며칠분인지, 상태
- 최근 입고·사용 기록 (날짜와 팩 수만 보이고, 직원 이름은 숨긴다)
- 받은 알림 기록

## 8. 예외 상황 처리

| 상황 | 처리 |
|---|---|
| 서버 연결 끊김 | 화면 위에 "서버 연결 안 됨"을 표시하고 입력 버튼을 막는다. 기기에 임시로 저장하지 않는다 |
| 두 기기가 같은 환자를 동시에 입력 | 서버가 기록 순서대로 처리하고, 저장한 뒤에는 최신 잔량을 돌려준다. 잔량 확인과 기록 추가는 한 트랜잭션 안에서 한다 |
| 잔량보다 많이 사용/폐기/반환 | "재고가 부족합니다"라고 알리고 저장하지 않는다. 입고를 먼저 하도록 안내한다 |
| 입고 취소로 잔량이 음수가 됨 | 취소를 막는다 |
| 이미 취소된 기록을 다시 취소 | 막는다 |
| 문자 발송 실패 | 실패로 기록하고 관리자 화면에 표시한다 |
| 퇴원한 환자에게 입력 | 막는다 |

## 9. 테스트

- **서버 자동 테스트 (pytest)**
  - 잔량 계산 (모든 기록 종류와 취소)
  - 부족 판정: 일수 기준과 팩 수 기준, 경계값, 평균 0
  - 중복 발송 방지, 발송 가능 시간이 아닐 때 대기, 대기 중 입고되면 발송 취소
  - 권한: 간호사가 관리자 기능 사용, 보호자가 다른 아기 조회, 취소 10분 규칙
  - 보호자 로그인 잠금
  - 동시 입력 시 잔량이 맞는지
- **문자 발송**: 개발 중에는 실제로 보내지 않고 기록만 남기는 "가짜 발송"을 쓰고, 연동 단계에서 시험용 번호로 실제 발송을 확인한다.
- **앱**: 주요 화면 흐름 UI 테스트와, 태블릿·폰 실기기 수동 점검 목록
- **시범 운영**: 가짜 데이터로 병동에서 연습한 뒤, 실제 환자 몇 명으로 1~2주 운영

## 11. 병원 측 확인 사항

**전산팀**
1. 내부 서버 1대를 둘 자리 (24시간 켜 두는 PC 또는 가상 서버)
2. 서버에서 문자/알림톡 업체 API로 나가는 연결 허용
3. 보호자가 쓰는 병원 와이파이에서 내부 서버에 접속할 수 있는지
4. 업무용 기기(갤럭시탭/폰)에 APK 설치가 허용되는지 (MDM 사용 여부)

**개인정보 담당자**
- 아기 이름, 등록번호, 보호자 전화번호를 저장하고 문자 업체에 전화번호를 넘기는 것에 대한 병원 정책 확인
- 보호자에게 문자 수신 동의를 받는 방법 (환자 등록 시 동의를 받고, 동의하지 않으면 해당 환자의 "알림 사용 여부"를 끈다)
