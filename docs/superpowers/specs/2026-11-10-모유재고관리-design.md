# 신생아실 모유 재고관리 앱 — 설계 문서

- 작성일: 2026-11-10
- 개정: 2026-11-10 — 보호자 조회를 병원 기기에서만 하도록 변경, 보호자 알림을 문자 대신 앱 알림으로 변경, 퇴원 환자 개인정보 말소 추가
- 개정: 2026-11-10 — 화면 예시 반영: 입고를 **보호자 제출(제출처 태블릿) → 간호사 수량 확인** 2단계로, 화면에는 이름 대신 **아기 ID** 표시, 제출처 태블릿 여러 대(이름 표시)
- 상태: 검토 대기

---

## 1. 목적

신생아 환자(약 59명)의 보호자가 유축해 얼려 오는 모유(한 번에 2~5팩)를 병원이 **팩 개수 단위**로 관리한다.

- 보호자는 병원의 **제출처 태블릿**에서 아기의 재고를 보고, 가져온 모유 팩 수를 입력(제출)한다.
- 간호사는 **입고 확인 대기** 목록에서 실제 받은 수량을 확인해 재고에 반영하고, 사용·폐기를 빠르고 정확하게 기록한다.
- 관리자는 환자별 재고 현황과 일별 사용량을 본다.
- 재고가 거의 떨어지면 **직원 기기의 앱에 알림**이 뜨고, 직원이 보호자에게 전달한다. 병원이 허용하면 보호자 휴대폰으로도 앱 푸시 알림을 보낸다.
- 화면에는 아기 이름 대신 **아기 ID**(병원 등록번호)를 보여 준다.

### 성공 기준
- 종이 장부 없이 앱만으로 59명의 모유 재고를 관리할 수 있다.
- 여러 기기(갤럭시탭, 갤럭시폰)에서 동시에 입력해도 잔량이 항상 일치한다.
- 재고가 부족해지면 직원이 따로 확인하지 않아도 직원 기기에 알림이 뜬다(같은 부족 상황에 중복 알림 없음).
- 다른 아기의 모유를 잘못 기록하는 실수를 확인 창으로 막는다.
- 기본 기능은 병원 내부망만으로 동작하고, 서버가 외부 인터넷에 연결할 필요가 없다.

## 2. 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 사용 기기 | 안드로이드 (갤럭시탭, 갤럭시폰) — 병원 기기 |
| 데이터 공유 | 여러 기기 공유, **병원 내부망 서버** (외부 클라우드 사용 안 함) |
| 개발 방식 | 안드로이드 네이티브 앱 + 내부 서버 |
| 재고 단위 | **팩 개수만** (ml, 유축일, 유효기간 관리 안 함) |
| 환자 선택 | 아기 ID 검색·선택 (바코드/QR 스캔 없음) |
| 아기 표시 | 화면에는 **아기 ID(등록번호)만**. 아기 이름은 저장만 하고 관리자의 환자 등록·수정 화면에서만 보인다 |
| 입고 방식 | **2단계**: 보호자가 제출처 태블릿에서 가져온 팩 수 입력 → 간호사가 실제 수량 확인(다르면 고침, 안 왔으면 반려) 후 재고 반영. 간호사가 직접 입고하는 방법도 유지 |
| 제출처 | 병원 태블릿 여러 대. 관리자가 기기마다 이름(제출처 1, 2…)을 정해 등록한다 |
| 재고 부족 알림 | **앱 알림**. 기본: 직원 기기 앱 알림 → 직원이 보호자에게 전달. 선택: 보호자 휴대폰 푸시 (병원이 외부 연결을 허용할 때만) |
| 알림 기준 | 남은 일수 기준(기본) + 사용 기록이 부족한 신규 환자는 남은 팩 수 기준 |
| 계정 | 직원(관리자/간호사) + 보호자 |
| 직원 로그인 | 아이디 + **본인이 직접 설정한 비밀번호** |
| 보호자 로그인 | 전화번호 + 아기 ID(등록번호). 등록된 제출처 태블릿에서만 |
| 보호자 조회·제출 장소 | **병원 제출처 태블릿에서만** (보호자 휴대폰으로 조회하지 않음) |
| 퇴원 환자 | 퇴원 처리는 관리자만, 30일 뒤 개인정보 자동 말소 |

## 3. 시스템 구성

```
[병원 기기: 갤럭시탭 / 갤럭시폰 앱]  ──병원 내부망(HTTPS)──▶  [내부 서버: API + DB]
  직원 입력·조회, 직원 알림,                                        │
  보호자 조회·제출(제출처 태블릿, 여러 대)                         │ (선택 기능, 병원이 외부 연결을 허용할 때만)
                                                                    ▼
                                                     [구글 푸시 서버(FCM)] ──▶ 보호자 휴대폰 (알림만 받음)
```

### 기술 구성
- **앱**: Kotlin + Jetpack Compose. 직원과 보호자가 같은 앱을 쓰고 로그인 화면에서 [직원]/[보호자] 탭을 고른다.
- **서버**: Python FastAPI + SQLite(WAL 모드). 병원 내부 서버 1대에 설치한다. 환자 59명·기기 몇 대 규모에는 SQLite로 충분하고, DB 프로그램을 따로 설치·관리할 필요가 없다.
- **직원 알림**: 앱이 켜져 있는 동안 1분마다 내부 서버에 새 알림이 있는지 확인하고, 새로 부족해진 환자가 있으면 안드로이드 알림(소리·진동)을 띄운다. 외부 인터넷이 필요 없다.
- **보호자 푸시 (선택)**: 서버가 구글 푸시 서버(FCM)로 알림을 보낸다. 서버의 외부 연결이 필요하므로 병원이 허용할 때만 만든다. 푸시 문구에는 아기 이름 등 개인정보를 넣지 않는다.
- **통신 보안**: 공용 기기와 병원 와이파이를 쓰므로 비밀번호가 평문으로 오가면 안 된다. 서버는 자체 서명 인증서로 HTTPS를 쓰고, 각 병원 기기는 처음 한 번 **서버 등록 QR**(서버 주소와 인증서 공개키 지문)을 찍어 그 서버만 믿는다(인증서 고정). 따라서 공인 인증서는 필요 없고, 서버가 바뀌어도 앱을 다시 만들 필요가 없다. 세부 설계는 `2026-11-10-2-1단계-서버보강-design.md`.

### 앱 배포
- Play 스토어를 쓰지 않는다. 병원 기기에 APK를 직접(또는 MDM으로) 설치한다.
- 보호자는 병원 기기로 조회하므로 보호자 휴대폰에 앱을 설치하지 않는다. 보호자 푸시(선택 기능)를 쓸 때만 보호자 휴대폰에 앱을 설치한다.
- 앱 업데이트: 앱은 실행할 때 서버에 최신 버전을 물어보고, 새 버전이 있으면 설치를 안내한다.

## 4. 데이터

### 4.1 환자 (patient)
| 필드 | 설명 |
|---|---|
| 등록번호 | 병원 환자번호. 중복 불가. **화면에 보이는 아기 ID**이고 보호자 로그인에 쓰인다 |
| 아기 이름 | 화면에는 보이지 않는다(관리자의 환자 등록·수정 화면만) |
| 병상 | |
| 보호자 이름 | |
| 보호자 전화번호 | 보호자 로그인과 직원의 보호자 연락에 쓰인다 |
| 상태 | 입원 / 퇴원 |
| 입원일, 퇴원일 | |
| 개인정보 말소일 | 비어 있으면 아직 말소 전 (4.6 참조) |
| 알림 사용 여부 | 기본값: 사용 |
| 개별 남은 일수 기준 | 비어 있으면 전체 설정을 따른다 |
| 개별 팩 수 기준 | 비어 있으면 전체 설정을 따른다 |
| 알림 상태 | 정상 / 부족 알림 보냄 (중복 알림 방지용) |

### 4.2 재고 기록 (stock_record)
기록은 수정하거나 삭제하지 않고 추가만 한다. 잘못 입력한 기록은 "취소" 기록으로 바로잡는다. (예외: 4.6 개인정보 말소)

| 필드 | 설명 |
|---|---|
| 환자 | |
| 종류 | 입고 / 사용 / 폐기 / 퇴원 반환 / 취소 |
| 팩 수 | 1 이상 |
| 폐기 사유 | 해동 후 남음 / 오염 / 기타 (폐기일 때만) |
| 취소 대상 | 취소한 기록의 번호 (취소일 때만) |
| 일시 | 서버 시각 |
| 입력 직원 | |
| 메모 | 선택 |

**현재 잔량** = 입고 − 사용 − 폐기 − 퇴원 반환. 취소된 기록은 계산에서 뺀다. 잔량 계산은 서버에서만 한다.

### 4.3 알림 기록 (notification)
환자, 만든 시각, 문구, 보호자 연락 완료(직원·시각·메모), 보호자 푸시 결과(보내지 않음 / 대기 / 성공 / 실패, 실패 사유).

### 4.4 직원 계정 (staff)
아이디(중복 불가), 이름, 역할(관리자 / 간호사), 비밀번호 해시(argon2), 임시 비밀번호 여부, 활성 여부.

### 4.5 설정 (settings)
| 항목 | 기본값 |
|---|---|
| 남은 일수 기준 | 2일 |
| 신규 환자 팩 수 기준 | 3팩 |
| 평균 계산 기간 | 최근 3일 |
| 보호자 푸시 발송 가능 시간 | 08:00 ~ 21:00 (직원 알림은 시간 제한 없음) |
| 직원 자동 로그아웃 | 아무 조작 없이 10분 |
| 보호자 자동 로그아웃 | 아무 조작 없이 1분 (병원 공용 기기) |
| 퇴원 후 개인정보 보관 기간 | 30일 (지나면 자동 말소) |
| 직원 알림 문구 | "{병상}번 {아기이름} 아기 모유 약 {남은일수}일분({남은팩}팩) 남음 — 보호자 연락 필요" |
| 보호자 푸시 문구 | "[OO병원 신생아실] 모유가 약 {남은일수}일분 남았습니다. 방문 시 모유를 가져와 주세요." (아기 이름 넣지 않음) |

### 4.6 퇴원과 개인정보 말소
- **퇴원 처리는 관리자만 한다.** 보호자 화면에는 퇴원이나 정보 삭제 버튼이 없다.
- 관리자가 퇴원 처리하면 남은 팩을 "퇴원 반환" 또는 "폐기"로 기록하고 퇴원 상태로 바꾼다. 이때부터 **보호자 로그인과 알림이 바로 중단된다.**
- 퇴원 후 **보관 기간(기본 30일, 설정에서 변경)**이 지나면 서버가 매일 자동으로 그 환자의 개인정보를 말소한다. 관리자는 기간을 기다리지 않고 바로 말소할 수도 있다(되돌릴 수 없다는 확인 창을 거친다).
- **말소할 때 지우는 것**: 아기 이름(→ "퇴원환자-{번호}"), 등록번호(→ "말소-{번호}", 같은 등록번호로 재입원 등록이 가능하도록), 보호자 이름, 보호자 전화번호, 재고 기록의 메모, 알림 기록의 문구와 연락 메모, 보호자 휴대폰 푸시 등록 정보.
- **말소해도 남기는 것**: 팩 수 기록(입고·사용·폐기·반환·취소, 일시, 입력 직원). 누구의 기록인지는 알 수 없지만 일별 사용량 통계가 정확하게 유지된다.
- 재고 기록은 추가만 한다는 원칙(4.2)의 예외는 말소 때 메모를 지우는 것 하나뿐이다.


### 4.7 제출처와 제출 기록 (2-3단계)
- **제출처(station)**: 이름(제출처 1, 2…, 중복 불가), 기기 토큰(해시로 저장), 활성 여부, 만든 시각
- **제출(submission)**: 환자, 제출처, 제출 팩 수, 제출 시각, 상태(확인 대기 / 확인 완료 / 반려), 확인한 팩 수, 처리한 직원, 처리 시각, 만들어진 입고 기록 번호, 반려 사유
- 제출은 재고에 바로 더해지지 않는다. 간호사가 확인해야 입고 기록이 생긴다.

## 5. 계정과 권한

| 기능 | 관리자 | 간호사 | 보호자 |
|---|:-:|:-:|:-:|
| 환자 목록·상세 조회 | ✅ | ✅ | 자기 아기만 |
| 가져온 모유 입력(제출) | ❌ | ❌ | ✅ (제출처 태블릿에서) |
| 입고 확인·반려 | ✅ | ✅ | ❌ |
| 입고 / 사용 / 폐기 | ✅ | ✅ | ❌ |
| 기록 취소 | 언제든 | 본인 기록, 10분 이내 | ❌ |
| 재고 부족 알림 받기, 보호자 연락 완료 표시 | ✅ | ✅ | ❌ |
| 전체 현황, 일별 사용량, CSV | ✅ | ❌ | ❌ |
| 환자 등록·수정·퇴원·개인정보 말소 | ✅ | ❌ | ❌ |
| 알림 관리 | ✅ | ❌ | ❌ |
| 설정, 직원 계정 관리, 제출처 태블릿 등록 | ✅ | ❌ | ❌ |

권한은 **서버에서** 확인한다. 앱이 버튼을 숨기는 것만으로는 막지 않는다.

### 직원 로그인
- 관리자가 계정을 만들면 임시 비밀번호가 발급된다.
- 처음 로그인할 때 새 비밀번호를 반드시 직접 설정해야 한다. 설정하기 전에는 다른 기능을 쓸 수 없다.
- 비밀번호는 8자 이상이고 영문과 숫자를 섞어야 한다.
- 비밀번호를 잊으면 관리자가 초기화하고, 다시 임시 비밀번호부터 시작한다.
- 10분 동안 아무 조작이 없으면 자동으로 로그아웃된다 (공용 태블릿 대비). 앱이 서버 연결 상태를 확인하려고 주기적으로 보내는 요청은 "조작"으로 치지 않는다.
- 같은 아이디로 로그인을 5번 연속 실패하면 10분 동안 잠긴다 (직원 계정은 모든 아기의 정보를 볼 수 있으므로).
- 아이디는 대소문자를 구분하지 않는다 (갤럭시 키보드의 첫 글자 자동 대문자 대비).

### 보호자 로그인 (제출처 태블릿에서)
- 관리자가 등록한 **제출처 태블릿에서만** 로그인할 수 있다(서버가 기기 토큰을 확인한다).
- 따로 가입하지 않는다. 직원이 환자를 등록할 때 입력한 **보호자 전화번호 + 아기 ID**가 일치하고 아기가 입원 중이면 로그인된다.
- 로그인한 뒤에는 같은 전화번호로 등록된 입원 중인 아기를 모두 보여 준다 (쌍둥이 등).
- 병원 공용 기기이므로 **1분 동안 조작이 없거나 [마치기]를 누르면 바로 로그아웃**되고 첫 화면으로 돌아간다.
- 같은 전화번호로 로그인을 5번 연속 실패하면 10분 동안 잠긴다.
- 아기가 퇴원하면 로그인할 수 없다.

## 6. 재고 부족 알림 규칙

### 판정
1. **사용 기록이 3일 이상인 환자** (첫 사용 기록일로부터 3일 이상 지남)
   - 하루 평균 = 오늘을 뺀 최근 3일 동안의 사용 팩 수 ÷ 3
   - 남은 일수 = 현재 잔량 ÷ 하루 평균
   - **남은 일수 ≤ 2일**이면 부족으로 본다.
   - 하루 평균이 0이면 남은 일수를 계산하지 않고 아래 2번 기준을 쓴다.
2. **신규 환자** (사용 기록 3일 미만): **남은 팩 ≤ 3팩**이면 부족으로 본다.
3. 잔량이 0이면 항상 부족이다.

기준값은 설정에서 바꿀 수 있고, 환자별로 따로 정할 수도 있다.

### 판정 시점
- 재고 기록이 생기거나 취소될 때마다 판정한다.
- 평균 계산 기간이 날마다 바뀌므로 매일 08:00에 전체 환자를 다시 판정한다.

### 직원 알림 (기본)
- 알림 상태가 **정상 → 부족**으로 바뀔 때 알림을 **한 번만** 만든다.
- 직원 기기의 앱은 1분마다 새 알림을 확인하고, 새 알림이 있으면 안드로이드 알림(소리·진동)을 띄운다. 직원 알림은 시간 제한 없이 바로 뜬다.
- 앱 홈 화면 위쪽에 **"보호자 연락 필요"** 목록을 보여 준다. 직원이 보호자에게 연락(면회 시 안내, 전화)한 뒤 **[연락 완료]**를 누르면 누가 언제 연락했는지 기록되고 목록에서 빠진다.
- 입고로 기준 위로 올라가면 알림 상태가 정상으로 돌아가고, 연락하지 않은 알림은 자동으로 정리된다. 다음에 다시 부족해지면 또 알림을 만든다.
- 알림 사용을 끈 환자와 퇴원한 환자는 알림을 만들지 않는다.

### 보호자 조회 화면 안내
- 보호자가 병원 기기로 조회할 때 아기의 재고가 부족하면 화면 맨 위에 **"모유가 약 N일분 남았습니다. 모유를 가져와 주세요"**를 크게 보여 준다.

### 보호자 휴대폰 푸시 (선택 기능)
- 병원이 서버의 외부 연결(구글 FCM)을 허용할 때만 만든다.
- 보호자가 원하면 휴대폰에 앱을 설치하고 병원 와이파이에서 한 번 등록(전화번호 + 아기 등록번호)한다. 그 뒤 직원 알림이 만들어질 때 그 휴대폰으로도 푸시를 보낸다. 휴대폰 앱에서는 재고를 조회하지 않는다(조회는 병원 기기에서).
- 발송 가능 시간(08:00~21:00)이 아니면 대기시켰다가 다음 08:00에 보낸다. 그때까지 입고되어 부족 상황이 풀렸으면 보내지 않는다.
- 푸시가 실패해도 직원 알림은 그대로 남으므로 직원이 연락할 수 있다.
- 세부 설계(등록 절차, 푸시 등록 정보 저장)는 이 기능을 만들기 전에 정한다.

### 상태 색상 (목록 화면)
- 🟢 충분 / 🟠 부족 / 🔴 잔량 0팩

## 7. 화면

태블릿에서는 목록과 상세를 2단으로 나란히 보여 준다(왼쪽 목록, 오른쪽 상세). 휴대폰에서는 한 화면씩 넘겨 본다.

### 공통
- **로그인**: [직원] / [보호자] 탭
- **최초 비밀번호 설정** (직원)

### 간호사
- **홈 (입고 확인 및 재고 관리)**: 화면 예시 기준
  - 맨 위 띠: 방금 처리한 결과(예: "DEMO-01 · 3팩 입고 확인 완료 · 현재 냉동 재고 8팩")
  - **입고 확인 대기 N건** 표: 아기 ID, 현재 냉동 재고, 제출 위치, 접수 시각, 제출 팩 수, [수량 확인]. 접기/펼치기
  - **"보호자 연락 필요"** 목록과 [연락 완료] (4단계)
  - **전체 재원 아기 보기 · N명**(펼치기): 아기 ID 검색 → 선택. 각 줄 `아기 ID | 남은 팩 | 상태`, 부족한 아기를 맨 위에
  - 선택한 아기의 **모유 재고 상세** 카드: "확정 냉동 재고 N팩"
- **환자 상세**
  - 큰 글씨로 남은 팩 수와 약 며칠분인지 보여 준다.
  - 큰 버튼: **[입고]** (숫자 버튼 1~10 + 메모), **[사용]** (기본 1팩, +/−), **[폐기]** (팩 수 + 사유)
  - **확인 창**: "**DEMO-10 아기**에게 **3팩 입고**하시겠습니까?" — 아기 ID를 크게 보여 준다.
- **수량 확인 창**: 제출 팩 수가 미리 채워지고 +/−로 실제 받은 수를 고친다. [확인] → 입고 기록 생성, [반려](사유 선택: 모유가 오지 않음 / 기타) → 재고 변화 없음
  - 최근 기록(일시, 종류, 팩 수, 입력 직원), 보호자 연락처, 알림과 연락 기록
  - 기록 취소 (권한 규칙은 5장을 따른다)

### 관리자 (간호사 화면 포함)
- **전체 현황**: 요약 숫자(입원 환자 수, 부족 환자 수, 연락 대기 수, 오늘 입고/사용 합계)와 환자별 표(병상, 이름, 남은 팩, 하루 평균, 남은 일수, 상태, 마지막 알림). "부족한 환자만 보기" 필터와 정렬을 지원한다.
- **일별 사용량**: 날짜를 고르면 환자별 입고·사용·폐기 팩 수와 합계를 보여 준다. 최근 7일/30일 막대그래프(전체 합계와 환자별), CSV 내보내기.
- **환자 관리**: 등록, 수정, 환자별 알림 기준·알림 사용 여부 설정, **퇴원 처리** (남은 팩을 반환 또는 폐기로 기록한 뒤 퇴원 상태로 바꾼다), **개인정보 말소** (보관 기간이 지나면 자동, 또는 관리자가 즉시. 4.6 참조)
- **알림 관리**: 알림 기록, 연락 완료 여부와 담당 직원, 문구 편집 (보호자 푸시를 쓰면 발송 결과와 다시 보내기)
- **설정·직원 관리**: 알림 기준값, 자동 로그아웃 시간, 개인정보 보관 기간, 직원 계정 추가·비활성화·비밀번호 초기화
- **제출처 태블릿 등록**: 관리자가 그 태블릿에서 로그인해 "이 기기를 제출처로 사용 · 이름"을 정한다. 이후 그 기기는 보호자 화면만 보여 준다. 제출처 목록과 비활성화

### 보호자 (제출처 태블릿)
화면 예시 01·02 기준. 위쪽에 "제출처 태블릿 · {아기 ID}"를 표시한다.
- 아기 선택 (여러 명일 때)
- **우리 아기 모유 재고**: "현재 확인된 냉동 모유 N팩"(크게). 재고가 부족하면 "모유를 가져와 주세요" 안내(4단계)
- "재고만 보고 마칠 수도 있어요" + [가져온 모유 입력] / [마치기]
- **가져온 모유 입력**: 팩 수 1~10 숫자 버튼 → [제출]
- **제출 접수 완료**: "방금 제출한 모유 N팩", "현재 확인된 냉동 재고 M팩", "제출한 N팩은 간호사 확인 후 재고에 반영됩니다" + [마치기]
- [마치기]나 1분 무조작 → 로그아웃, 첫 화면

## 8. 예외 상황 처리

| 상황 | 처리 |
|---|---|
| 서버 연결 끊김 | 화면 위에 "서버 연결 안 됨"을 표시하고 입력 버튼을 막는다. 기기에 임시로 저장하지 않는다 |
| 두 기기가 같은 환자를 동시에 입력 | 서버가 기록 순서대로 처리하고, 저장한 뒤에는 최신 잔량을 돌려준다. 잔량 확인과 기록 추가는 한 트랜잭션 안에서 한다 |
| 잔량보다 많이 사용/폐기/반환 | "재고가 부족합니다"라고 알리고 저장하지 않는다. 입고를 먼저 하도록 안내한다 |
| 입고 취소로 잔량이 음수가 됨 | 취소를 막는다 |
| 이미 취소된 기록을 다시 취소 | 막는다 |
| 두 직원이 같은 알림에 [연락 완료] | 먼저 누른 직원만 기록되고, 다른 직원 화면에서는 목록에서 빠진다 |
| 보호자 푸시 실패 (선택 기능) | 실패로 기록하고 관리자 화면에 표시한다. 직원 알림은 그대로 남는다 |
| 퇴원한 환자에게 입력 | 막는다 |
| 같은 제출을 두 직원이 동시에 확인 | 먼저 처리한 직원만 반영되고, 다른 직원에게는 "이미 처리된 제출입니다" |
| 확인 대기 중에 아기가 퇴원 | 확인할 수 없고 반려만 할 수 있다 |

## 9. 테스트

- **서버 자동 테스트 (pytest)**
  - 잔량 계산 (모든 기록 종류와 취소)
  - 부족 판정: 일수 기준과 팩 수 기준, 경계값, 평균 0
  - 중복 알림 방지, 입고로 정상 복귀 시 알림 정리, 연락 완료 기록
  - 권한: 간호사가 관리자 기능 사용, 보호자가 다른 아기 조회, 취소 10분 규칙
  - 보호자 로그인 잠금, 보호자 1분 자동 로그아웃
  - 동시 입력 시 잔량이 맞는지
  - 개인정보 말소: 30일 경계, 지우는 항목과 남기는 항목, 말소 후 같은 등록번호 재등록
- **보호자 푸시 (선택 기능)**: 개발 중에는 실제로 보내지 않고 기록만 남기는 "가짜 발송"을 쓰고, 연동 단계에서 시험용 휴대폰으로 확인한다.
- **앱**: 주요 화면 흐름 UI 테스트와, 태블릿·폰 실기기 수동 점검 목록 (직원 알림 소리·진동 포함)
- **시범 운영**: 가짜 데이터로 병동에서 연습한 뒤, 실제 환자 몇 명으로 1~2주 운영

## 10. 단계별 계획표

| 단계 | 이름 | 하는 일 | 끝났다고 보는 기준 |
|---|---|---|---|
| 0 | 병원 측 준비 (개발과 동시에 진행) | 전산팀 확인(아래 11장), 제출처 태블릿 마련(대수·위치), 아기 등록번호 형식 확인, 개인정보 담당자 확인 | 전산팀과 개인정보 담당자 답변 |

| 2 | 앱: 간호사 기능 | 로그인, 환자 목록과 검색, 상세, 입고·사용·폐기와 확인 창, 태블릿 2단/폰 1단, 연결 끊김 표시, 자동 로그아웃, HTTPS 인증서 고정. **실사용 전 서버 보강**: DB 구조 버전 관리(마이그레이션 도구 Alembic)와 인덱스, 직원 로그인 5회 실패 잠금. 2-1 서버 보강(`2026-11-10-2-1단계-서버보강-design.md`) → 2-2 간호사 앱(`2026-11-10-2-2단계-간호사앱-design.md`) 순서로 진행. 병원 기기는 서버 등록 QR을 한 번 찍어 서버를 등록한다. 앱만으로 시범 사용이 되도록 **간단한 관리자 화면(환자 등록·수정, 직원 관리)을 2-2에 포함**한다. 화면은 예시 디자인(청록색 카드, 아기 ID)을 따른다 | 두 기기에서 동시에 입력해도 잔량 일치 → **실사용 가능** |
| 2-3 | 제출처 태블릿과 입고 확인 | **먼저** 마이그레이션 안전장치 보강(`transactional_ddl`, 2-1 계획 완료 기록 참조). 제출처 등록·기기 토큰, 보호자 로그인(제출처에서만, 잠금, 1분 자동 로그아웃), 보호자 조회·가져온 모유 입력, 간호사 입고 확인 대기·수량 확인·반려. 설계 `2026-11-10-2-3단계-제출처-design.md` | 보호자 제출 → 간호사 확인 → 재고 반영이 여러 제출처에서 맞게 동작 |
| 3 | 관리자 기능 | 전체 현황, 일별 사용량과 그래프, CSV, 퇴원 처리, 퇴원 후 개인정보 자동·즉시 말소, 직원 계정 관리, 설정 | 관리자가 하루 사용량과 전체 재고 확인 가능 |
| 4 | 재고 부족 알림 (직원 앱 알림) | 부족 판정, 중복 방지, 직원 기기 알림(1분 확인, 소리·진동), "보호자 연락 필요" 목록과 연락 완료 기록, 문구 편집 | 재고가 기준 아래로 내려가면 모든 직원 기기에 1분 안에 알림, 중복 없음 |
| 5 | (2-3으로 옮김) | 보호자 화면은 2-3 제출처 태블릿에 포함. 남는 것: 부족 안내 문구(4단계 이후) | — |
| 6 | 시범 운영 | 가짜 데이터 연습, 실제 환자 몇 명으로 1~2주 운영, 의견 반영 | 간호사들이 종이 장부 없이 쓸 수 있다고 동의 |
| 7 | 설치·운영 | 정식 설치, 매일 DB 파일 자동 백업(30일 보관), 간호사용·보호자용 설명서 각 1장 | 59명 등록 완료, 정식 사용 시작 |
| 선택 | 보호자 휴대폰 푸시 | 병원이 외부 연결(구글 FCM)을 허용하면: 보호자 휴대폰 등록, 푸시 발송, 발송 시간 제한, 실패 처리 | 시험용 휴대폰으로 푸시 수신, 중복 없음 |

## 11. 병원 측 확인 사항

**전산팀**
1. 내부 서버 1대를 둘 자리 (24시간 켜 두는 PC 또는 가상 서버)
2. 업무용 기기(갤럭시탭/폰)와 제출처 태블릿에 APK 설치가 허용되는지 (MDM 사용 여부). Android 17 이상 기기는 앱의 **'근처 기기(로컬 네트워크)' 권한**이 있어야 내부 서버에 연결된다 — 설치할 때 허용하거나 MDM으로 미리 허용
3. 병원 기기가 연결되는 와이파이에서 내부 서버의 앱용 포트 하나에 접속할 수 있는지
4. (보호자 푸시를 쓸 경우에만) 서버에서 구글 푸시 서버(FCM)로 나가는 연결 허용, 보호자 휴대폰이 등록할 때 병원 와이파이에서 서버에 한 번 접속할 수 있는지

**개인정보 담당자**
- 아기 이름, 등록번호, 보호자 전화번호를 내부 서버에 저장하는 것에 대한 병원 정책 확인
- 퇴원 후 개인정보 보관 기간 (기본 30일이 병원 정책에 맞는지)
- (보호자 푸시를 쓸 경우) 보호자 동의 절차. 푸시 문구에는 개인정보를 넣지 않는다.
