- 작성일: 2026-11-13
- 상위 설계: `2026-11-10-모유재고관리-design.md`(5장 계정과 권한, 7장 보안), 2-3 설계 `2026-11-10-2-3단계-제출처-design.md`
- 근거: 사용자 요청. 로그인 창에서 간호사와 제출자(보호자)로 나뉘어 로그인하게 한다.
- 상태: 확정(2026-11-13 사용자 확인). 계획은 하나로 쓴다(서버 2개 작업 + 앱 작업).

## 1. 목표와 결정

서버를 등록한 병원 기기의 로그인 화면에서 **[간호사·직원]**과 **[보호자 (모유 제출)]** 중 하나를 골라 로그인한다.

### 사용자와 확정한 결정 (2026-11-13)
- **제출처 모드는 유지한다.** 보호자 전용 태블릿이 필요하면 지금처럼 관리자가 제출처로 바꾼다. 해제는 숨은 길게 누르기로 한다.
- **보호자 로그인은 서버를 등록한 모든 기기에서 허용한다.** 기기 토큰 없이도 된다.
  - 받아들인 위험: 서버 QR을 찍은 기기면 개인 휴대폰에서도 보호자 로그인이 된다.
  - 보완 장치
    - 기기(IP)별 실패 잠금(3.2)
    - 전화번호별 잠금
    - 1분 세션 만료
    - 서버 QR 보관 안내(6장)

### 범위 밖
- 보호자 휴대폰 앱(상위 설계의 푸시 수신용)은 이번에 만들지 않는다.
- 일반 기기에서 보호자가 제출하면, "제출 위치"에는 기기 이름 대신 "병원 기기"를 표시한다.

## 2. 데이터 (마이그레이션 0003)

- `submission.station_id`를 비어 있어도 되게 바꾼다(일반 기기에서 온 제출).
- `guardian_session.station_id`를 비어 있어도 되게 바꾼다(일반 기기 세션).
- 기존 데이터는 그대로 둔다.
  - 표를 다시 만들어야 하므로 기존 `foreign_keys_off` 방식을 쓴다.
  - 2-1·2-3a의 마이그레이션 안전장치(버전별 트랜잭션, 외래 키 검사)를 그대로 따른다.

## 3. 서버

### 3.1 보호자 API의 제출처 토큰
- `X-Station-Token`을 **선택 사항**으로 바꾼다.
  - **보낸 경우:** 지금과 같다. 토큰이 없는 값이거나 비활성 제출처의 것이면 401 `station_invalid`. 세션은 그 제출처에 묶인다.
  - **보내지 않은 경우:** 일반 기기 세션이다. 세션의 `station_id`는 비어 있다.
- 세션을 확인할 때는 세션이 만들어진 방식과 요청 방식이 같아야 한다.
  - 제출처 세션: 같은 제출처 토큰과 함께 와야 한다.
  - 일반 기기 세션: 제출처 토큰 없이 와야 한다.
  - 다르면 401 "로그인이 필요합니다".

### 3.2 일반 기기 로그인 잠금
- 전화번호 잠금(5번 → 10분)은 그대로 둔다.
- **새 잠금:** 제출처 토큰 없이 들어온 보호자 로그인 실패를 **요청한 IP(`request.client.host`) 기준으로 센다.** 10분 안에 20번 실패하면 그 IP의 토큰 없는 보호자 로그인을 10분 동안 막는다.
  - 429 "잠시 뒤에 다시 시도해 주세요"
  - 키는 `guestip:{IP}`, 제출처 잠금과 같은 설정값을 쓴다.
- IP를 알 수 없으면 키 `guestip:unknown`으로 함께 센다.

### 3.3 제출과 대기 목록
- 일반 기기 세션의 제출은 `submission.station_id`가 비어 있다.
- `GET /submissions?status=pending`의 `station_name`
  - 제출처에서 온 제출: 제출처 이름
  - 일반 기기에서 온 제출: **"병원 기기"**
- 확인할 때 만드는 입고 기록 메모
  - 제출처에서 온 제출: "{제출처 이름} 제출분(제출 n팩)"
  - 일반 기기에서 온 제출: "병원 기기 제출분(제출 n팩)"

## 4. 앱

### 4.1 로그인 화면 (일반 기기)
- 맨 위에 큰 선택 버튼 두 개를 둔다(높이 64dp 이상).
  - **[간호사·직원]**: 고르면 지금의 아이디·비밀번호 로그인
  - **[보호자 (모유 제출)]**: 고르면 보호자 화면(2-3의 보호자 흐름)으로 간다.
- 마지막에 고른 쪽을 기억하지 않는다. 공용 기기라서 매번 선택 화면부터 시작한다.
- "서버 다시 등록" 같은 기존 링크는 직원 쪽 화면에 그대로 둔다.

### 4.2 보호자 흐름 (일반 기기)
- 2-3의 보호자 화면을 그대로 쓴다.
  - 조회 → 가져온 모유 입력 → 접수 완료 → [마치기]
  - 1분 무조작이면 자동 로그아웃한다.
- 차이점은 네 가지다.
  - 제출처 토큰 없이 요청한다.
  - 머리글은 "보호자 확인"이다(제출처 이름 대신).
  - 숨은 관리자 해제 영역과 "제출처 무효" 화면은 없다.
  - [마치기]를 누르거나 1분이 지나면 **로그인 선택 화면**으로 돌아간다. 입력과 이전 아기 정보는 모두 비운다.
- 보호자 화면에서 뒤로 가기를 누르면 선택 화면으로 돌아간다. 로그인돼 있었으면 로그아웃한다.
- 직원 세션과 보호자 세션은 동시에 존재하지 않는다. 보호자로 들어가면 직원 세션이 없는 상태여야 한다(로그인 화면은 원래 직원 세션이 없을 때만 보인다).

### 4.3 제출처 모드
- 바뀌지 않는다. 제출처 태블릿은 선택 화면 없이 보호자 화면만 보여 준다.

### 4.4 새 문구
- `login_choose_title` "누구로 들어가시나요?"
- `login_role_staff` "간호사·직원"
- `login_role_guardian` "보호자 (모유 제출)"
- `guardian_general_header` "보호자 확인"
- `login_back_to_choice` "← 처음으로"
- 서버 표시값 "병원 기기"는 서버가 보낸다.

## 5. 예외

- **같은 기기에서 보호자가 연달아 쓴다:** 1분 자동 로그아웃과 [마치기]로 처음 화면에 돌아간다. 다음 사람에게 이전 정보가 남지 않는다.
- **같은 IP에서 여러 번호로 실패가 몰린다:** 10분 동안 잠긴다. 병원 와이파이가 NAT로 IP를 하나로 묶어도, 서버는 내부망에 있으므로 보통 기기별 IP가 보인다.
- **일반 기기에서 로그인한 보호자 토큰을 제출처 토큰과 함께 보낸다:** 401(세션 방식 불일치)
- **개인 휴대폰:** 기술적으로 막을 수 없다. 6장의 운영 안내로 대응한다.

---

## 6. 기획서·운영 반영

- 기획서 보안 항목: "보호자는 등록된 제출처 태블릿에서만"을 "보호자는 병원 기기(서버를 등록한 기기)의 로그인 화면에서 선택해 로그인"으로 바꾼다.
- 기획서에 받아들인 위험과 보완 장치(IP 잠금, 전화번호 잠금, 1분 만료)를 적는다.
- 병원 측 확인 사항에 추가한다: "서버 등록 QR은 신생아실에 보관하고, 보호자나 개인 휴대폰으로 찍지 않도록 안내"

## 7. 테스트

- **서버**
  - 0003 적용(데이터 있는 DB, 기존 제출·세션 유지)과 표 정의 일치
  - 토큰 없는 보호자 로그인·조회·제출·로그아웃
  - 세션 방식 불일치 401(양쪽 방향)
  - IP 잠금(20번)과 다른 IP는 영향 없음
  - 전화번호 잠금 유지
  - 대기 목록 "병원 기기"와 확인 메모
  - 제출처 쪽 기존 테스트가 모두 통과해야 한다.
- **앱**
  - 로그인 선택 → 직원 로그인(기존 흐름)
  - 로그인 선택 → 보호자 흐름(토큰 없이 요청) → [마치기]·1분 → 선택 화면, 입력 비움
  - 뒤로 가기 동작
  - 제출처 모드는 선택 화면을 보이지 않음
  - 에뮬레이터와 실제 서버로 일반 기기 보호자 제출 → 간호사 확인("병원 기기")을 끝까지 확인
