## 1. 목표

보호자가 병원의 **제출처 태블릿**에서 가져온 모유 팩 수를 직접 입력하고, 간호사가 **실제 받은 수량을 확인**해야 재고에 반영되도록 한다. 원래 5단계였던 보호자 화면을 여기서 만든다.

### 범위
- **서버 먼저**: 마이그레이션 안전장치 보강(`transactional_ddl=True`와 끝까지 확인하는 테스트, 2-1 계획 완료 기록 참조). 그 뒤 새 마이그레이션 0002(제출처, 제출, 보호자 세션)
- 제출처 태블릿 등록(관리자)과 기기 토큰
- 보호자 로그인(제출처에서만), 조회, 가져온 모유 입력
- 간호사 홈의 입고 확인 대기 표, 수량 확인, 반려
- 3단계 이후: 부족 안내 문구(4단계 판정이 생긴 뒤)

## 2. 데이터 (마이그레이션 0002)

| 표 | 칸 |
|---|---|
| `station` | id, name(중복 불가, 1~20자), token_hash(SHA-256, 중복 불가), active, created_at, created_by(staff) |
| `submission` | id, patient_id, station_id, count(1~10), submitted_at, status(`pending`/`confirmed`/`rejected`), confirmed_count(1~100, 확인했을 때만), handled_by(staff), handled_at, intake_record_id(만들어진 입고 기록), reject_reason(`not_received`/`other`), memo |
| `guardian_session` | id, token_hash, phone, station_id, created_at, last_seen_at |

- `submission.status`가 `pending`일 때만 처리할 수 있다. 처리하면 다시 바꿀 수 없다(잘못 확인한 경우 직원이 입고 기록을 취소한다).
- 보호자 로그인 실패 기록은 기존 `login_attempt`를 키 `guardian:{전화번호}`로 함께 쓴다.

## 3. 서버 API

### 제출처 관리 (관리자)
- `POST /stations` `{name}` → `{station: {id, name, active}, station_token}`
  - 토큰은 이때 한 번만 돌려준다. 그 태블릿의 앱이 저장한다.
- `GET /stations`, `PATCH /stations/{id}` `{active}`
  - 비활성화하면 그 기기의 보호자 세션이 모두 끝난다.

### 보호자 (요청마다 헤더 `X-Station-Token` 필수, 비활성·없는 토큰이면 401 "등록된 제출처 기기가 아닙니다")
- `POST /guardian/login` `{phone, baby_id}` → `{token, babies: [...]}`
  - 같은 전화번호의 입원 중인 아기 목록을 돌려준다.
  - 실패하면 401 "전화번호 또는 아기 ID가 올바르지 않습니다".
  - 같은 전화번호로 5번 실패하면 10분 잠금(429).
- `GET /guardian/babies` → `[{patient_id, baby_id, balance}]` (보호자 토큰 필요, 자기 아기만)
- `POST /guardian/submissions` `{patient_id, count}` → `{submission: {id, count, submitted_at}, balance}`
  - count는 1~10. 자기 아기만. 퇴원한 아기는 409.
- `POST /guardian/logout`
- 보호자 세션은 1분 동안 요청이 없으면 만료된다.

### 간호사·관리자
- `GET /submissions?status=pending` → `[{id, patient_id, baby_id, balance, station_name, submitted_at, count}]` (접수 시각순)
- `POST /submissions/{id}/confirm` `{count}` → `{record, balance, submission}`
  - INTAKE 기록을 만든다. 메모: "{제출처 이름} 제출분(제출 {n}팩)"
  - 이미 처리됐으면 409 "이미 처리된 제출입니다". 퇴원한 아기는 409.
- `POST /submissions/{id}/reject` `{reason, memo?}` → `{submission}`

## 4. 앱

### 4.1 제출처 모드
- 관리자 메뉴에 **"이 기기를 제출처로 사용"**을 둔다. 이름을 입력하면 서버에 등록하고, 받은 토큰을 기기에 저장한다.
  - 저장 위치는 DataStore이고, 가능하면 Android Keystore로 암호화한다.
- 그다음 앱은 **보호자 화면만** 보여 준다.
- 제출처 모드를 끄려면 관리자가 로그인해야 한다(화면 구석 길게 누르기 → 관리자 로그인 → 해제).

### 4.2 보호자 화면 (예시 01·02)
1. 첫 화면: "제출처 태블릿 · {제출처 이름}". 보호자 전화번호와 아기 ID를 입력하고 [확인]
2. 아기가 여러 명이면 아기 ID 목록에서 고른다.
3. **우리 아기 모유 재고**: "현재 확인된 냉동 모유 **N팩**"
   - "재고만 보고 마칠 수도 있어요"
   - [가져온 모유 입력] / [마치기]
4. **가져온 모유 입력**: 숫자 버튼 1~10 → 확인 창("{아기 ID} 아기 모유 N팩을 제출합니다") → 제출
5. **제출 접수 완료**: "방금 제출한 모유 N팩", "현재 확인된 냉동 재고 M팩", "제출한 N팩은 간호사 확인 후 재고에 반영됩니다" + [마치기]
6. [마치기]를 누르거나 1분 동안 조작이 없으면 로그아웃하고 첫 화면으로 돌아간다.

### 4.3 간호사 홈 (예시의 첫 화면)
- **입고 확인 대기 N건** 표: 아기 ID, 현재 냉동 재고, 제출 위치, 접수 시각(오후 2시 13분 형식), 제출 팩 수, [수량 확인]
  - 30초마다(연결 확인과 함께) 새로고침한다.
- **수량 확인 창**: "{아기 ID} · {제출처} · {접수 시각}". 제출 팩 수가 미리 채워져 있고, +/−로 실제 받은 수를 고친다.
  - [확인]: 입고 반영. 결과 띠에 "{아기 ID} · N팩 입고 확인 완료 · 현재 냉동 재고 M팩"
  - [반려]: 사유(모유가 오지 않음 / 기타)를 고른다. 재고는 바뀌지 않는다.
- 예시 03처럼 확인이 끝나면 "실제 받은 모유 N팩 / 현재 확인된 냉동 모유 M팩 / 기존 K팩 + 확인한 N팩"을 보여 준다.

## 5. 예외

- 같은 제출을 두 간호사가 동시에 확인 → 한 명만 반영되고, 다른 한 명에게는 "이미 처리된 제출입니다". BEGIN IMMEDIATE로 직렬화한다.
- 확인 대기 중 퇴원 → 확인할 수 없고 반려만 할 수 있다.
- 보호자가 같은 아기를 연속으로 제출 → 각각 대기 목록에 오른다. 간호사가 실제 수량으로 확인하거나 반려한다.
- 제출처 기기 분실 → 관리자가 그 제출처를 비활성화하면 즉시 쓸 수 없게 된다.

## 6. 테스트

- **서버**
  - 마이그레이션 0002 적용(데이터가 있는 DB 포함)과 표 정의 일치
  - 안전장치 보강의 끝까지 확인하는 테스트
  - 제출처 토큰 없음·비활성이면 401
  - 보호자 로그인 잠금
  - 남의 아기 조회·제출 403
  - 제출 → 확인 → 잔량 증가, 수량을 고친 확인, 반려(잔량 그대로)
  - 이중 확인 동시성
  - 퇴원한 아기 확인 막기
  - 보호자 세션 1분 만료
- **앱**
  - 제출처 모드 전환과 해제
  - 보호자 흐름(조회 → 입력 → 접수 완료 → 자동 로그아웃)
  - 간호사 대기 표 → 수량 확인 → 결과 띠
  - 에뮬레이터 두 대(제출처 + 간호사)로 끝까지 확인
