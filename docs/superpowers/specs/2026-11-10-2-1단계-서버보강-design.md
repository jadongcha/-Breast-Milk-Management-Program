# 2-1단계 서버 보강 — 설계 문서

- 작성일: 2026-11-10
- 상위 설계: `docs/superpowers/specs/2026-11-10-모유재고관리-design.md` (10장 2단계 "실사용 전 서버 보강")
- 상태: 검토 대기

2단계는 두 계획으로 나눈다. **2-1 서버 보강**(이 문서)을 먼저 하고, **2-2 간호사 앱**을 이어서 한다. 2-1이 끝나야 앱이 처음부터 HTTPS로 서버에 붙을 수 있다.

---

## 1. 목표

1. 병원 와이파이와 공용 기기에서도 비밀번호와 환자 정보가 노출되지 않도록 **HTTPS로만** 통신한다.
2. 병원 기기 앱이 **서버 등록 QR**을 한 번 찍어서 진짜 병원 서버를 알아보게 한다.
3. 앞으로 DB에 칸을 더해도 기존 데이터를 지키도록 **DB 구조 버전 관리(Alembic)**를 도입한다.
4. 직원 계정을 비밀번호 대입 공격으로부터 지키도록 **로그인 5회 실패 잠금**을 넣는다.

### 범위 밖
- 앱에서 QR을 찍고 인증서를 확인하는 부분 → 2-2
- 보호자 로그인 잠금 → 5단계 (같은 방식을 재사용)

## 2. HTTPS와 서버 등록 QR

### 2.1 인증서 만들기 명령: `milkbank-setup-tls`
서버를 설치할 때 관리자가 `server/`에서 한 번 실행한다.

```
uv run milkbank-setup-tls --host 192.168.0.10 [--host milkbank.local] [--port 8443] [--new-key]
```

- `--host`: 기기가 서버에 접속할 주소. IP 또는 이름이며, 여러 개를 줄 수 있다(1개 이상 필수). 인증서의 주소 목록(SAN)에 모두 들어간다. QR에는 첫 번째 주소를 쓴다.
- `--port`: 기본 8443.
- 만드는 파일 (DB 파일이 있는 폴더 아래 `tls/`, 기본 `server/data/tls/`):
  - `server.key` — 개인키 (EC P-256). **이미 있으면 그대로 다시 쓴다.** `--new-key`를 줄 때만 새로 만든다.
  - `server.crt` — 자체 서명 인증서. 유효기간 10년. 실행할 때마다 새로 만든다(주소 추가·만료 대비).
  - `server-qr.png` — 서버 등록 QR 이미지.
  - `server.json` — 접속 주소와 포트 (서버 실행 명령이 읽는다).
- 화면 출력: 접속 주소, 인증서 확인값, QR 파일 위치, "이 QR을 출력해 신생아실에 보관하세요" 안내. Windows 콘솔에서도 한글이 깨지지 않게 한다(1단계 CLI와 같은 방식).
- 잘못된 주소(빈 값, 공백 포함 등)는 한국어 오류 메시지와 종료 코드 1.

### 2.2 QR 내용
JSON 문자열 하나를 담는다.

```json
{"type": "milkbank-server", "v": 1, "url": "https://192.168.0.10:8443", "pin": "sha256/<공개키 SHA-256의 Base64>"}
```

- `pin`은 인증서의 **공개키(SPKI) 지문**이다. 인증서를 다시 만들어도 키가 같으면 값이 바뀌지 않으므로 기기에서 QR을 다시 찍을 필요가 없다. `--new-key`를 쓰면 바뀌므로 모든 기기에서 다시 등록해야 한다(명령이 이 경고를 출력한다).
- QR에는 비밀 정보가 없다. 개인키는 서버 밖으로 나가지 않는다.

### 2.3 서버 실행 명령: `milkbank-serve`
```
uv run milkbank-serve
```
- `tls/server.json`, `server.crt`, `server.key`를 읽어 HTTPS로만 실행한다. 바인드 주소는 `0.0.0.0`, 포트는 `server.json`의 값.
- 인증서가 없으면 실행하지 않고 "먼저 milkbank-setup-tls를 실행하세요"를 출력하고 종료 코드 1.
- 암호화하지 않은 HTTP 포트는 열지 않는다.
- 개발과 테스트에서는 지금처럼 TestClient를 쓴다(HTTPS 불필요).

## 3. DB 구조 버전 관리 (Alembic)

### 3.1 방식
- 마이그레이션 파일은 서버 패키지 안(`milkbank/migrations/`)에 둔다. SQLite에서 표를 바꿀 수 있도록 batch 모드를 쓴다.
- **첫 마이그레이션(기준선)**은 1단계 표 구조 전체와 새 표·인덱스를 만든다.
  - 새 인덱스 `ix_stock_record_patient_id` — 환자별 기록 조회
  - 새 부분 유니크 인덱스 `ux_stock_record_cancel_target` — `stock_record(target_id) WHERE kind = 'cancel'`. 같은 기록을 두 번 취소하는 일을 DB에서도 막는다.
  - 새 표 `login_attempt` (4장)
- 모델 코드에도 같은 인덱스를 선언해서 코드의 표 정의와 마이그레이션 결과가 일치하게 한다.

### 3.2 서버가 켜질 때
- 지금의 "표 만들기(init_db)"를 **"마이그레이션 적용"**으로 바꾼다. 서버 앱, 첫 관리자 생성 명령, 테스트 모두 같은 함수를 쓴다.
- DB 파일이 없으면 새로 만들고 최신 버전까지 적용한다.
- DB 파일이 있고 적용할 마이그레이션이 남아 있으면:
  1. 먼저 DB 파일을 `backups/milkbank-<UTC 시각>-before-<목표 버전>.db`로 복사한다 (DB 폴더 아래).
  2. 최신 버전까지 적용한다.
- 이미 최신이면 아무것도 하지 않고 백업도 만들지 않는다.
- 표는 있는데 버전 기록이 없는 DB(1단계 때 만든 테스트용 DB)는 열지 않고, "1단계 테스트용 DB는 지원하지 않습니다. 파일을 지우고 다시 시작하세요"를 알린다. 1단계 DB에는 실제 데이터가 없다.

### 3.3 확인
- 마이그레이션으로 만든 DB와 모델 코드의 표 정의를 비교해서 차이가 있으면 실패하는 테스트를 둔다. 나중에 칸을 추가하고 마이그레이션을 빠뜨리면 바로 드러난다.

## 4. 직원 로그인 잠금

### 4.1 규칙
- 같은 아이디(소문자로 바꾼 값 기준)로 **5번 연속 실패하면 10분 동안 잠근다.**
- 잠긴 동안에는 비밀번호를 확인하지 않고 바로 거부한다. 비밀번호가 맞아도 거부한다. 실패 횟수도 늘리지 않는다.
  - 응답: `429`, `"로그인을 5번 실패해 10분 동안 잠겼습니다. 잠시 후 다시 시도해 주세요"`
- 잠금이 끝나면 실패 횟수 0에서 다시 센다.
- 로그인에 성공하면 그 아이디의 실패 기록을 지운다.
- **없는 아이디와 비활성 계정에도 똑같이 적용한다.** 실패 응답은 지금과 같은 `401 "아이디 또는 비밀번호가 올바르지 않습니다"`.
- **응답 시간 맞추기**: 없는 아이디일 때도 미리 만들어 둔 가짜 해시로 비밀번호 확인을 한 번 수행해서, 있는 아이디와 걸리는 시간이 비슷하게 한다.
- 관리자가 그 직원의 **비밀번호를 초기화하면 잠금도 풀린다**(실패 기록 삭제).
- 기준값(5회, 10분)은 설정값으로 둔다. 3단계에서 설정 화면으로 옮긴다.

### 4.2 데이터
새 표 `login_attempt`:

| 칸 | 설명 |
|---|---|
| username | 소문자 아이디. 기본키 |
| failed_count | 연속 실패 횟수 |
| locked_until | 잠금이 끝나는 시각(UTC). 잠기지 않았으면 비어 있음 |

### 4.3 주의: 실패 기록은 반드시 저장한다
지금 서버는 오류 응답을 보낼 때 그 요청의 DB 변경을 모두 되돌린다. 로그인 실패 기록만은 **오류 응답과 상관없이 저장**되어야 한다. 그렇지 않으면 잠금이 동작하지 않는다. 테스트로 확인한다(실제 HTTP 요청 5번 → 6번째 429).

## 5. 테스트

- **인증서·QR**: SAN에 모든 `--host`가 들어가는지, 유효기간 10년, `pin`이 공개키 지문과 같은지, 키 재사용 시 `pin` 유지·`--new-key` 시 변경, QR을 다시 읽으면 2.2의 JSON과 같은지, 잘못된 주소 거부
- **서버 실행 명령**: 인증서가 없으면 종료 코드 1과 안내 문구 (실제 서버를 띄우지 않고 확인)
- **마이그레이션**: 새 DB 생성, 표 정의 일치, 적용 전 백업 생성, 최신이면 백업 없음, 버전 기록 없는 기존 DB 거부, 이중 취소를 DB 인덱스가 거부
- **잠금**: 5번째 실패에서 잠김, 잠긴 동안 맞는 비밀번호도 429, 10분 정각·10분 1초 경계, 성공 시 초기화, 없는 아이디도 잠김, 비활성 계정, 비밀번호 초기화 시 잠금 해제, HTTP 요청으로 실패 기록이 실제 저장됨
- 1단계 테스트 97개는 그대로 모두 통과해야 한다.

## 6. 새로 필요한 라이브러리

- `alembic` — DB 구조 버전 관리
- `cryptography` — 인증서와 키 생성
- `qrcode` (PNG 출력 지원 포함) — 서버 등록 QR 이미지

## 7. 운영 안내 (README에 반영)

설치 순서:
1. `uv sync`
2. `uv run milkbank-setup-tls --host <서버 내부 IP>` → `server-qr.png` 출력해 보관
3. `uv run milkbank-create-admin --username admin --name 관리자`
4. `uv run milkbank-serve`

- 서버 PC의 Windows 방화벽에서 8443 포트 들어오는 연결 허용 (전산팀)
- `data/` 폴더(DB, 백업, 개인키)는 서버 PC 밖으로 복사하지 않는다. 개인키가 새면 `--new-key`로 다시 만들고 모든 기기에서 다시 등록한다.
