# 팩별 용량 — 서버 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 재고를 팩 단위로 관리해 팩마다 용량(mL)을 저장하고, 남은 mL·용량 모름 팩 수를 모든 재고 응답에 더한다.

**Architecture:** 새 `pack` 표와 서비스 모듈 `packs.py`. `stock.add_record`/`cancel_record`가 팩을 만들고·내보내고·되돌린다. 잔량(`stock.balance`)은 기존 기록 계산 그대로 두고, 재고 팩 수와 항상 같다는 것을 테스트로 지킨다. 응답의 남은 mL는 `packs.summary`에서 온다.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2, Alembic, SQLite, pytest (`uv run pytest -W error`)

**Spec:** `docs/superpowers/specs/2026-11-15-팩별용량-design.md`

## Global Constraints

- 쓰기는 BEGIN IMMEDIATE 한 트랜잭션, 함수의 첫 쿼리가 쓰기 잠금. 오류는 `DomainError`(BadRequest 400 / Conflict 409 …), 메시지는 아래 한국어 그대로.
- 팩 용량: 정수 1~1000, 빈 값 허용. 벗어나면 400 "팩 용량은 1~1000mL 사이여야 합니다".
- `pack_mls` 길이 ≠ 팩 수 → 400 "팩마다 용량 칸 수가 맞지 않습니다".
- 고른 팩이 그 아기 재고에 없거나 수가 다르거나 겹침 → 409 "고른 팩을 다시 확인해 주세요".
- 입고 취소 때 그 입고의 팩이 하나라도 나갔으면 → 409 "이 입고의 팩이 이미 사용되었습니다. 사용 기록을 먼저 취소해 주세요".
- 기본으로 나가는 팩: 입고 시각이 이른 순, 같으면 팩 번호 순.
- 기록의 `ml` = 그 기록으로 들어오거나 나간 팩 중 용량을 아는 팩의 합(없으면 null), `ml_unknown` = 모르는 팩 수. 쓸 때 계산해 저장하고, 읽을 때 다시 계산하지 않는다. 취소 기록은 대상의 `ml`·`ml_unknown`을 복사.
- 남은 mL(`balance_ml`) = 재고 팩 중 아는 용량의 합(없으면 0), `unknown_ml_packs` = 재고 팩 중 모르는 수.
- 기록 입력 API의 `ml`은 받지 않는다(무시). 3단계의 `validate_ml`(1~20000)은 더 이상 입력 검증에 쓰지 않는다.
- 팩 표에는 개인정보가 없다 — 말소가 건드리지 않는다.
- 기존 테스트는 고치지 않고 통과해야 한다. 허용: 마이그레이션 head 번호(0004 → 0005)와 백업 이름, 응답 필드 추가, 3단계 mL **입력** 테스트(기록·제출·확인에 `ml`을 넣던 테스트)를 이 설계 규칙(`pack_mls`)으로 바꾸는 것 — 바꾼 테스트는 보고서에 목록으로 남긴다.
- 커밋 끝 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **잔량과 재고 팩 수가 어긋남** — 입고·사용·폐기·반환·취소를 섞은 어떤 순서에서도 `stock.balance == 재고 팩 수`. → Task 2 `test_balance_equals_pack_count_after_mixed_sequence`.
2. **두 기기가 같은 팩을 동시에 내보냄** — 한쪽만 성공하거나 둘 다 다른 팩. → Task 2 `test_concurrent_use_takes_distinct_packs`(기존 동시성 테스트 방식).
3. **기존 DB 업그레이드** — 취소가 섞인 실제 기록에서 재고 팩 수 = 기존 잔량, 아니면 업그레이드가 통째로 되돌려진다. → Task 1 `test_upgrade_0004_builds_packs_matching_balance`, `test_upgrade_0004_aborts_on_mismatch`.
4. **보호자가 3팩에 칸을 2개만 보냄 / 1001mL** — 400 메시지, 제출 안 됨. → Task 3 `test_submit_pack_mls_validation`.
5. **확인할 때 팩 수를 바꿈** — 보호자 목록이 잘리거나 빈 칸이 더해진다. → Task 3 `test_confirm_resizes_guardian_pack_mls`.
