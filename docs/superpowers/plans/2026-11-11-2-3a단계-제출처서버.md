# 2-3a 제출처 서버 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버에 다음을 더한다.
- 제출처 태블릿 등록과 기기 토큰
- 보호자 로그인·조회·제출
- 간호사 입고 확인·반려

**Architecture:** 기존 FastAPI 서버에 서비스 모듈 3개와 라우터 3개를 더한다.
- 서비스: `stations.py`, `guardians.py`, `submissions.py`
- 라우터: `api/stations.py`, `api/guardian.py`, `api/submissions.py`

모든 쓰기는 기존처럼 `BEGIN IMMEDIATE` 트랜잭션 하나로 처리한다. 확인은 기존 `stock.add_record`로 INTAKE 기록을 만든다.

먼저 마이그레이션 안전장치를 보강한 뒤 0002를 추가한다.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, SQLite, Alembic, pytest

**Spec:** `docs/superpowers/specs/2026-11-10-2-3단계-제출처-design.md` (확정본). 상위: `docs/superpowers/specs/2026-11-10-모유재고관리-design.md`

**Branch:** `feature/stations` (`feature/nurse-app` c3c70f0에서 분기)

## Global Constraints

- 새 의존성을 추가하지 않는다.
- 테스트는 `server/`에서 `uv run pytest -W error`로 돌리고 모두 통과해야 한다. 지금은 174개다.
- 모든 트랜잭션은 `BEGIN IMMEDIATE`(`db.py`)로 시작한다. 각 서비스 함수의 **첫 쿼리**가 쓰기 잠금을 잡도록 순서를 지킨다(`stock.py` 머리말과 같은 규칙).
- DB 시각은 tz-aware UTC(`UTCDateTime`)이고, 현재 시각은 `Clock`으로만 얻는다.
- 사용자에게 보이는 오류 문구는 아래 계획에 적힌 한국어를 **그대로** 쓴다.
- 오류는 `errors.py`의 `DomainError` 하위 클래스로 낸다. 응답은 `{"detail": 문구}`이고, `code`가 있으면 `{"detail", "code"}`다(Task 3).
- 토큰은 `security.new_token()`으로 만들고, `hash_token`으로 해시한 값만 저장한다.
- 전화번호는 `patients.normalize_phone`으로 맞춘다.
- 설정값은 `config.Config`에 둔다(Task 3·4에서 추가).
  - `guardian_idle_seconds = 60`
  - `station_lock_threshold = 20`
  - `station_lock_window_minutes = 10`
  - `station_lock_minutes = 10`
  - `pending_limit = 5`
  - 보호자 전화번호 잠금은 기존 `login_lock_threshold`(5)와 `login_lock_minutes`(10)를 쓴다.
- 커밋 메시지 끝에는 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.

## Review Focus

1. **보호자가 쓰는 도중 관리자가 그 제출처를 사용 중지했다.** 다음 요청은 401 `station_invalid`여야 한다. → Task 3·4 테스트
2. **전화번호를 "010-1234-5678"이나 "010 1234 5678"로 입력했다.** 저장된 번호(숫자만)와 같게 보고 로그인돼야 한다. 아기 ID도 앞뒤 공백과 대소문자 차이(" demo-01 ")를 무시하고 맞춰야 한다. → Task 4 테스트
3. **보호자가 제출한 뒤 아기가 퇴원했다.** 확인은 409 "퇴원한 아기입니다. 반려만 할 수 있습니다"이고, 반려는 되어야 한다. 대기 목록에서는 `discharged: true`다. → Task 5 테스트
4. **토큰을 섞어 썼다.** 다음 경우는 모두 401이어야 한다. → Task 4 테스트

   - 제출처 A에서 받은 보호자 토큰을 제출처 B의 토큰과 함께 보냄
5. **보호자 세션 1분 경계.** 마지막 요청 뒤 정확히 60초면 아직 유효하고, 61초면 만료다. 요청할 때마다 시간이 연장돼야 한다. → Task 4 테스트

    - 실패를 센다.
    - `window_minutes`가 있으면 마지막 실패가 그보다 오래됐을 때 1부터 다시 센다.

  - `DomainError`에 선택 인자 `code: str | None = None`을 더한다.

    - 사용 중인 같은 이름이 있으면 409 "이미 있는 제출처 이름입니다".
    - (Station, 원래 토큰)을 돌려준다.

    - 이미 중지됐으면 그대로 돌려준다.

      - (원래 토큰, 아기 목록)을 돌려준다.

      - 다른 제출처의 세션
      - `now - last_seen_at > guardian_idle_seconds`. 만료된 세션은 지운다.

**Interfaces:**
- Consumes: `current_guardian`, `guardians.guardian_babies`(Task 4), `stock.add_record`, `stock.balance`, `stock.record_view`, `RecordOut`
- Produces (submissions.py)
  - `def submit(db, clock, config, *, session: GuardianSession, patient_id: int, count: int) -> Submission`
    - 첫 쿼리는 환자 조회다.
    - 없거나 `guardian_phone != session.phone`이면 403 "본인 아기만 제출할 수 있습니다".
    - 퇴원했으면 409 "퇴원한 아기입니다".
    - count가 1~10이 아니면 400 "팩 수는 1~10 사이여야 합니다".
    - PENDING이 이미 `config.pending_limit`(5)건이면 409 "확인을 기다리는 제출이 많습니다. 간호사에게 말씀해 주세요".
  - `@dataclass class PendingView: id, patient_id, baby_id, balance, station_name, submitted_at, count, discharged: bool`
  - `def pending(db) -> list[PendingView]`: `submitted_at`, `id`순
  - `def confirm(db, clock, *, submission_id: int, count: int, staff: Staff) -> tuple[Submission, StockRecord]`
    - 첫 쿼리는 제출 조회다.
    - 없으면 404 "제출을 찾을 수 없습니다".
    - PENDING이 아니면 409 "이미 처리된 제출입니다".
    - 퇴원했으면 409 "퇴원한 아기입니다. 반려만 할 수 있습니다".
    - count가 1~100이 아니면 400 "팩 수는 1~100 사이여야 합니다".
    - `stock.add_record(kind=INTAKE, count=count, staff=staff, memo=f"{제출처 이름} 제출분(제출 {n}팩)")`
    - 상태를 CONFIRMED로 바꾸고 `confirmed_count`, `handled_by`, `handled_at`, `intake_record_id`를 채운다.
  - `def reject(db, clock, *, submission_id: int, reason: RejectReason, memo: str | None, staff: Staff) -> Submission`
    - 404와 409(이미 처리됨)는 confirm과 같다.
    - 메모는 앞뒤 공백을 잘라 쓴다.
    - `OTHER`인데 메모가 없으면 400 "기타 사유를 입력해 주세요".
    - 메모가 100자를 넘으면 400 "메모는 100자 이하로 입력해 주세요".
    - 퇴원한 아기도 반려할 수 있다.

  - `POST /submissions/{id}/reject` `{reason, memo?}` → 200 `{submission: SubmissionOut}`
