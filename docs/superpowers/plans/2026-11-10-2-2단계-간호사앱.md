# 모유 재고관리 — 2-2단계 간호사 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 병원 기기용 안드로이드 앱을 만든다. 서버 등록 QR과 공개키 지문 확인 HTTPS, 직원 로그인·비밀번호 변경, 환자 목록·상세와 입고·사용·폐기·취소, 간단한 관리자 화면(환자 등록·수정, 직원 관리)이 들어간다. 서버 기록 응답에는 `staff_id`를 추가한다.

**Architecture:** 액티비티 1개 + Compose Navigation. 화면마다 ViewModel(StateFlow)을 두고, 서버 호출은 Repository를 거친다. 통신은 OkHttp/Retrofit을 쓰고, `SpkiPinTrustManager`가 QR의 pin과 서버 공개키를 비교한다. 로그인 상태는 메모리의 `SessionManager`에만 둔다. 서버 주소·pin은 DataStore에 둔다. 연결 확인(`ConnectionMonitor`)과 자동 로그아웃(`IdleWatcher`)은 앱 전체에서 공유한다.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3, BOM), Navigation Compose, Lifecycle ViewModel, kotlinx.coroutines, kotlinx.serialization, Retrofit, OkHttp, DataStore Preferences, CameraX, ML Kit Barcode Scanning(bundled), material3-adaptive. 테스트: JUnit4, kotlinx-coroutines-test, Turbine, OkHttp MockWebServer + okhttp-tls, Compose UI Test.

**Spec:** `docs/superpowers/specs/2026-11-10-2-2단계-간호사앱-design.md` (상위: `2026-11-10-모유재고관리-design.md`, 서버: `2026-11-10-2-1단계-서버보강-design.md`)

## 서버 API (앱이 쓰는 것)

| 메서드·경로 | 용도 |
|---|---|
| `GET /health` | 연결 확인·서버 등록 확인 (인증 없음) |
| `POST /auth/login` `{username,password}` → `{token, must_change_password, staff}` | 로그인 |
| `POST /auth/logout`, `POST /auth/password` `{current_password,new_password}`, `GET /auth/me` | 로그아웃·비밀번호·내 정보 |
| `GET /patients?q=`, `GET /patients/{id}` (records 포함), `POST /patients`, `PATCH /patients/{id}` | 환자 |
| `POST /patients/{id}/records` `{kind: intake/use/discard, count, discard_reason?, memo?}` → `{record, balance}` | 입고·사용·폐기 |
| `POST /records/{id}/cancel` → `{record, balance}` | 취소 |
| `GET /staff`, `POST /staff` `{username,name,role}` → `{staff, temp_password}`, `PATCH /staff/{id}` `{active}`, `POST /staff/{id}/reset-password` → `{temp_password}` | 직원 관리 |

기록의 `kind` 응답 값은 `in/use/discard/return/cancel`, `discard_reason`은 `thawed_leftover/contaminated/other`, `role`은 `admin/nurse`, 시각은 UTC ISO-8601이다.

### Task 4: 공개키 지문 확인 HTTPS 클라이언트

**Files:** `server/SpkiPinTrustManager.kt`, `server/HttpClientFactory.kt` / Test: `SpkiPinTrustManagerTest.kt`, `HttpClientFactoryTest.kt`

**Interfaces:**
- Produces:
  - `class SpkiPinTrustManager(pin: String) : X509TrustManager`
    - `checkServerTrusted`: 체인의 첫 인증서(leaf) 공개키 DER(SubjectPublicKeyInfo)의 SHA-256을 Base64로 만들어 `"sha256/..."`와 비교한다.
    - 다르거나 체인이 비면 `CertificateException`. `checkClientTrusted`는 항상 예외. `getAcceptedIssuers`는 빈 배열.

  - `object HttpClientFactory`
    - `fun okHttp(config: ServerConfig, session: SessionManager?, debugLogging: Boolean): OkHttpClient`
      - `SpkiPinTrustManager`로 만든 `SSLContext`를 쓴다.
      - `hostnameVerifier`는 항상 true다(지문으로 대신함).
      - 타임아웃: 연결 5초, 읽기 10초.
      - 디버그 로깅은 `Authorization`을 가린다.
    - `fun retrofit(config: ServerConfig, client: OkHttpClient): Retrofit` (kotlinx.serialization converter, `ignoreUnknownKeys = true`)
  - `SessionManager`는 Task 5에서 정의한다. 이 Task에서는 `null`만 넘겨 테스트한다.

- [ ] **Step 1: 실패하는 테스트** (okhttp-tls `HeldCertificate`로 EC 인증서 생성, `MockWebServer.useHttps`)

### Task 5: API, 오류 처리, 세션, 저장소

**Files:** `api/MilkbankApi.kt`, `api/Dto.kt`, `api/ErrorMapping.kt`, `core/Result.kt`, `core/Time.kt`, `session/SessionManager.kt`, `data/*Repository.kt`, `AppContainer.kt` / Test: `ErrorMappingTest.kt`, `TimeTest.kt`, `SessionManagerTest.kt`, `RepositoriesTest.kt`(MockWebServer, HTTP)

**Interfaces:**
- Consumes: Task 4 `HttpClientFactory`, Task 3 `ServerConfig`
- Produces:
  - `data class ApiError(val status: Int?, val message: String)`. `status == null`이면 네트워크 오류이고, `message`는 `network_error` 문구다.
  - `sealed interface ApiResult<out T> { data class Ok<T>(val value: T); data class Err(val error: ApiError) }`
  - `suspend fun <T> apiCall(networkErrorMessage: String, block: suspend () -> T): ApiResult<T>`
    - `HttpException`이면 본문 JSON의 `detail`(문자열)을 꺼낸다. 없으면 `networkErrorMessage`.
    - `IOException`이면 `ApiError(null, networkErrorMessage)`.
  - DTO: 서버 API 표의 요청·응답. `StaffDto(id, username, name, role, active, mustChangePassword)`, `PatientDto(..., balance)`, `PatientDetailDto(... records)`, `RecordDto(id, kind, count, discardReason, targetId, memo, staffId, staffName, createdAt: Instant, canceled)`. `Instant`용 serializer를 둔다.
  - `fun formatKst(instant: Instant): String` → `"yyyy-MM-dd HH:mm"` (Asia/Seoul)
  - `class SessionManager(clock: Clock)`
    - `val state: StateFlow<Session?>`, `data class Session(token, staff: StaffDto)`
    - `fun start(token, staff)`, `fun end(reason: LogoutReason)`
    - `val events: SharedFlow<LogoutReason>`, `enum LogoutReason { USER, EXPIRED, IDLE }`
  - OkHttp 인터셉터(`HttpClientFactory`에 연결)
