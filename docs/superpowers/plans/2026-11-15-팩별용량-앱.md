# 팩별 용량 — 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱에서 팩마다 용량을 입력하고, 남은 팩·남은 mL·남은 팩 목록을 보고, 사용·폐기 때 나갈 팩을 미리 보거나 고른다.

**Architecture:** 기존 패턴(Retrofit DTO + Repository `ApiResult` + ViewModel StateFlow + Compose). 팩별 칸의 상태와 검사는 순수 Kotlin(`ui/components/PackMls.kt`)으로 만들어 간호사 입고·보호자 제출·수량 확인이 함께 쓴다. 3단계의 총 mL 칸(`MlField`, `parseMl`)은 이 칸으로 바뀐다.

**Tech Stack:** Kotlin, Jetpack Compose (Material3), Retrofit + kotlinx.serialization; JUnit + coroutines-test + turbine; compose-ui-test.

**Spec:** `docs/superpowers/specs/2026-11-15-팩별용량-design.md` (서버는 `2026-11-15-팩별용량-서버.md`로 완료)

## Global Constraints

- 서버 응답·요청(서버 계획 완료분): 입고 요청 `pack_mls`(팩 수만큼, 칸마다 null 허용), 사용·폐기 요청 `pack_ids`(선택); `RecordDto.mlUnknown`; `RecordResultDto/ConfirmResponse/GuardianSubmitResponse/BabyDto/PatientDto/OverviewRowDto`의 `balance_ml`, `unknown_ml_packs`; `PatientDetailDto.packs`(id, ml, created_at); 보호자 제출 `pack_mls`; 대기 목록 `pack_mls`; 확인 요청 `pack_mls` — **확인 요청은 `pack_mls`를 항상 보낸다**(기본값 없는 필드).
- 팩 용량 칸: 숫자만, 비우면 모름, 1~1000. 벗어나면 칸 아래 "팩 용량은 1~1000mL 사이여야 합니다"(`pack_ml_range_error`)를 보이고 저장·제출 버튼을 막는다.
- 문구(그대로):
  - `pack_ml_label` "팩 %d (mL)", `pack_ml_all_label` "모두 같은 용량(mL)", `pack_ml_hint` "모르면 비워 두세요"
  - 재고: `stock_with_ml` "%1$d팩 · %2$dmL", `stock_unknown_suffix` " · 용량 모름 %d팩"(남은 mL가 0이고 모두 모르면 "%d팩 · 용량 모름"=`stock_all_unknown`), 0팩이면 지금 문구 그대로
  - 기록 줄: 모두 알면 "3팩 · 240mL", 일부 모르면 "3팩 · 160mL (용량 모름 1팩)"(`record_ml_partial`), 모두 모르면 "3팩"
  - 남은 팩 목록: `remaining_packs_title` "남은 팩", 줄 "%1$s 입고 · %2$s"(날짜 KST "M월 d일", 용량 "80mL" 또는 `pack_ml_unknown` "용량 모름")
  - 사용·폐기 창: `packs_to_go` "나갈 팩: %s"(예 "80mL, 80mL"), `choose_packs` "팩 고르기", `choose_packs_done` "고르기 완료"
- 화면에는 아기 ID만, 버튼 56dp 이상, 보호자 화면 64dp 이상, 보호자 60초 자동 로그아웃·다음 보호자에게 남지 않음 — 그대로.
- 기존 테스트는 고치지 않고 통과. 허용: 3단계 총 mL(`MlField`/`parseMl`/`ml` 요청) 테스트를 팩별 규칙으로 바꾸는 것(보고서에 목록), 생성자·데이터 클래스 인자 추가에 따른 호출부 수정.
- `./gradlew testDebugUnitTest assembleDebug compileDebugAndroidTestKotlin` 전부 통과. 커밋 끝 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **팩 수를 바꾸면 칸이 줄거나 늘어남** — 적어 둔 값은 앞에서부터 유지, 늘어난 칸은 빈 칸. → Task 1 `resize_keepsLeadingValues`.
2. **"모두 같은 용량"을 지운 뒤** — 칸 값은 그대로 남는다(지우기만으로 모두 비우지 않는다). → Task 1 `fillAll_clearingDoesNotWipe`.
3. **팩 고르기에서 팩 수와 다른 수를 고름** — 완료 버튼이 막힌다. → Task 2 `choosePacks_requiresExactCount`.
4. **보호자 화면에서 칸이 10개** — 스크롤되고 버튼이 가려지지 않는다(화면 테스트에서 10팩 선택 후 [제출]이 보이는지). → Task 4 `guardian_tenPacks_submitVisible`.
5. **용량 모르는 팩만 남음** — "N팩 · 용량 모름"으로 보이고 "0mL"이 아니다. → Task 1 `stockText_allUnknown`.
