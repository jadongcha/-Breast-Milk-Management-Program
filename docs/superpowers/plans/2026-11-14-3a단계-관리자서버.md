# 3a단계 관리자 서버 + mL 선택 입력 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버에 mL 선택 입력, 설정 표, 부족 판정과 전체 현황, 일별 사용량·그래프·CSV, 퇴원 처리, 개인정보 즉시·자동 말소를 더한다.

**Architecture:** 기존 서비스 모듈 패턴(서비스 함수 + `api/*.py` 라우터 + pydantic 스키마 + `DomainError`)을 따른다. 새 서비스 모듈: `settings.py`(설정 표), `judge.py`(부족 판정, 순수 함수), `reports.py`(현황·일별·그래프·CSV), `discharge.py`(퇴원·말소). 새 라우터 `api/admin.py`(`/admin/*`). 스키마 변경은 마이그레이션 0004 하나로 한다.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2, Alembic, SQLite, pytest (`uv run pytest -W error`)

**Spec:** `docs/superpowers/specs/2026-11-14-3단계-관리자기능-design.md` (상위: `2026-11-10-모유재고관리-design.md`)

## Global Constraints

- 모든 쓰기 트랜잭션은 BEGIN IMMEDIATE이고 함수의 첫 쿼리가 쓰기 잠금을 잡는다. 오류는 `errors.py`의 `DomainError` 하위 클래스(BadRequest 400, Forbidden 403, NotFound 404, Conflict 409)로, 메시지는 아래 한국어 그대로.
- 재고 기록은 추가만 한다. 예외는 말소 때 메모를 지우는 것 하나(상위 설계 4.6).
- 날짜 계산은 한국 시각(`clock.KST`). DB 시각은 UTC.
- mL: 선택, 정수 1~20000. 벗어나면 BadRequest "용량은 1~20000mL 사이여야 합니다". 재고·잔량·판정은 팩 기준 그대로.
- 관리자 전용 API는 `require_admin`(간호사 403 "관리자만 사용할 수 있습니다").
- 화면 표시용 아기 식별자는 `reg_no`(아기 ID). 응답에 아기 이름을 넣지 않는다(새 관리자 API 모두).
- 설정 기본값: days_threshold 2 (1~30), packs_threshold 3 (1~50), avg_days 3 (1~14), staff_idle_minutes 10 (1~60), retention_days 30 (1~365). 범위 오류 메시지: "{이름}은(는) {min}~{max} 사이여야 합니다" — 이름: 남은 일수 기준 / 신규 환자 팩 수 기준 / 평균 계산 기간 / 직원 자동 로그아웃 / 개인정보 보관 기간.
- 기존 테스트는 고치지 않고 통과해야 한다. 허용되는 변경: 마이그레이션 head 번호(0003 → 0004)와 백업 파일 이름, 응답에 필드가 늘어난 것.
- 커밋 메시지는 기존처럼 한국어 conventional style, 끝 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **KST 날짜 경계** — 한국 시각 00:00 직전/직후(UTC 14:59/15:00)에 남긴 기록은 다른 날로 세야 한다. → Task 5 `test_daily_kst_boundary`.
2. **취소된 기록** — 통계·판정·CSV 어디에서도 취소된 기록과 취소 기록 자체를 세지 않는다. → Task 4 `test_judge_inputs_skip_canceled`, Task 5 `test_daily_skips_canceled`.
3. **보호자 mL를 확인 때 잃지 않기** — 확인 요청에 `ml`이 아예 없으면 보호자가 적은 값을 쓴다(구버전 앱). `ml: null`을 보내면 지운다. → Task 2 `test_confirm_ml_default_and_clear`.
4. **같은 전화번호의 다른 입원 아기(쌍둥이)** — 한 아기만 퇴원하면 보호자 세션은 남아야 한다. → Task 6 `test_discharge_keeps_session_for_twin`.
5. **말소 경계** — 퇴원일 + 보관일 당일(KST)에 말소, 하루 전에는 안 함. 말소된 환자 수정 금지, 같은 등록번호 재등록 가능. → Task 6 `test_auto_erase_boundary`, `test_erased_cannot_be_edited`, `test_reregister_after_erase`.

판정 규칙(상위 설계 6장, 설정 값 사용):
```
if balance == 0: status = "empty"
used_days = (today - first_use_day).days if first_use_day else 0
if first_use_day and used_days >= avg_days:
    daily_avg = recent_use_packs / avg_days
    if daily_avg > 0:
        days_left = balance / daily_avg
        status (balance>0) = "low" if days_left <= days_threshold else "enough"
        return
# 신규 환자 또는 평균 0
daily_avg = (위에서 계산했으면 그 값, 아니면 None); days_left = None
status (balance>0) = "low" if balance <= packs_threshold else "enough"
```
