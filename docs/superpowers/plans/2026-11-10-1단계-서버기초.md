# 모유 재고관리 — 1단계 서버 기초 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 직원 로그인(최초 비밀번호 설정 포함), 환자 등록·수정·조회, 재고 입고/사용/폐기/취소와 잔량 계산을 제공하는 내부 서버 API를 만든다. 권한 검사와 자동 테스트를 포함한다.

**Architecture:** FastAPI 앱이 HTTP와 권한 검사를 맡고, 업무 규칙은 프레임워크에 묶이지 않은 서비스 모듈(`staff.py`, `patients.py`, `stock.py`)에 둔다. 서비스는 `errors.py`의 도메인 예외를 던지고, API가 이를 `{"detail": "<한국어 메시지>"}` 응답으로 바꾼다. 데이터는 SQLite 파일 하나에 저장한다. 모든 트랜잭션을 `BEGIN IMMEDIATE`로 시작해서, 잔량 확인과 기록 추가가 원자적으로 처리된다.

**Tech Stack:** Python 3.12, uv, FastAPI, SQLAlchemy 2.x(동기), SQLite, argon2-cffi, pydantic v2, pytest, httpx(TestClient)

**Spec:** `docs/superpowers/specs/2026-11-10-모유재고관리-design.md` (이 계획은 10장 "1단계 서버 기초"를 구현한다)

## Global Constraints

- 모든 서버 코드는 `server/` 아래에 두고, 명령은 `server/`에서 `uv run ...`으로 실행한다.
- 사용자에게 보이는 오류 메시지는 모두 한국어로, 이 계획에 적힌 문구를 그대로 쓴다.
- 시각은 UTC로 저장한다. "오늘"과 "날짜"는 Asia/Seoul 기준이다.
- 재고 기록은 추가만 한다. UPDATE나 DELETE를 하지 않는다. 바로잡을 때는 `cancel` 기록을 추가한다.
- 권한은 서버에서 검사한다.
- 직원 자동 로그아웃: 마지막 요청 후 **10분**. 간호사의 기록 취소 가능 시간: 입력 후 **10분**(10분 정각까지 허용).
- 비밀번호: **8자 이상, 영문과 숫자를 모두 포함**.
- 팩 수: 1 이상 100 이하 (상한 100은 입력 실수를 막기 위해 이 계획에서 정한 값).
- SQLite 설정: `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`. 모든 트랜잭션은 `BEGIN IMMEDIATE`로 시작.
- 인증: `Authorization: Bearer <token>`. 토큰 원문은 DB에 저장하지 않고 SHA-256 해시만 저장한다.

## Review Focus

1. **보호자 전화번호 형식이 제각각** — `010-1234-5678`, `010 1234 5678`, `01012345678`을 모두 `01012345678`로 저장해야 한다. 4단계 알림과 5단계 보호자 로그인이 이 값에 의존한다. → Task 5 `test_phone_is_normalized`
2. **병상 번호 정렬** — `"2"`, `"10"`, `"1"`이 문자열 순서가 아니라 `1, 2, 10` 순서로 나와야 한다. → Task 5 `test_list_sorted_by_bed_naturally`
3. **비활성화되거나 비밀번호가 초기화된 직원의 기존 로그인** — 즉시 무효가 되어야 한다. 공용 태블릿에 로그인이 남아 있는 상황이다. → Task 4 `test_deactivate_kills_sessions`, `test_reset_password_kills_sessions`
4. **등록번호 앞뒤 공백** — `" A123 "`과 `"A123"`은 같은 환자로 보고 중복 등록을 막아야 한다. → Task 5 `test_reg_no_trimmed_and_unique`
5. **두 기기가 같은 기록을 동시에 취소** — 한쪽만 성공해야 한다(이중 취소로 잔량이 틀어지면 안 됨). → Task 6 `test_concurrent_cancel_only_one_succeeds`

```python
engine = create_engine(f"sqlite:///{db_path}", connect_args={"check_same_thread": False})

@event.listens_for(engine, "connect")
def _on_connect(dbapi_conn, _):
    dbapi_conn.isolation_level = None
    cur = dbapi_conn.cursor()
    cur.execute("PRAGMA journal_mode=WAL")
    cur.execute("PRAGMA foreign_keys=ON")
    cur.execute("PRAGMA busy_timeout=5000")
    cur.close()

@event.listens_for(engine, "begin")
def _on_begin(conn):
    conn.exec_driver_sql("BEGIN IMMEDIATE")
```

### Task 3: 직원 로그인, 세션, 비밀번호 변경, 첫 관리자 생성

**Files:**
- Create: `server/src/milkbank/staff.py`, `schemas.py`(직원 관련 부분), `main.py`, `cli.py`, `api/__init__.py`, `api/deps.py`, `api/auth.py`
- Modify: `server/tests/conftest.py` (클라이언트 픽스처와 헬퍼 추가)
- Test: `server/tests/test_api_auth.py`

**Interfaces:**
- Consumes: Task 1의 모델·`Clock`·`Config`·예외, Task 2의 보안 유틸
- Produces:
  - `staff.py`
    - `create_staff(db, clock, *, username: str, name: str, role: Role) -> tuple[Staff, str]`: 아이디는 앞뒤 공백을 제거하고, 빈 값이면 `BadRequest("아이디를 입력해 주세요")`. 중복이면 `Conflict("이미 사용 중인 아이디입니다")`. 임시 비밀번호를 만들고 `must_change_password=True`로 저장한다. 반환값은 `(직원, 임시 비밀번호)`.
    - `login(db, clock, username: str, password: str) -> tuple[Staff, str]`: 없는 아이디, 틀린 비밀번호, 비활성 계정은 모두 `Unauthorized("아이디 또는 비밀번호가 올바르지 않습니다")`. 성공하면 `AuthSession`을 만들고 `(직원, 토큰 원문)`을 돌려준다.
    - `authenticate(db, clock, raw_token: str | None, idle_minutes: int) -> Staff`: 토큰이 없거나 모르는 토큰이면 `Unauthorized("로그인이 필요합니다")`. `now - last_seen_at > idle_minutes`이면 세션을 지우고 `Unauthorized("세션이 만료되었습니다. 다시 로그인해 주세요")`. 직원이 비활성이면 `Unauthorized("로그인이 필요합니다")`. 통과하면 `last_seen_at = now`로 갱신한다.
    - `logout(db, raw_token: str) -> None`
    - `change_password(db, staff: Staff, current: str, new: str) -> None`: 현재 비밀번호가 틀리면 `BadRequest("현재 비밀번호가 올바르지 않습니다")`. 정책 위반이면 `BadRequest(<정책 메시지>)`. 새 비밀번호가 현재와 같으면 `BadRequest("새 비밀번호는 현재 비밀번호와 달라야 합니다")`. 성공하면 `must_change_password=False`.
    - `delete_sessions(db, staff_id: int) -> None`
  - `schemas.py`: `StaffOut{id, username, name, role, active, must_change_password}`, `LoginIn{username, password}`, `LoginOut{token, must_change_password, staff: StaffOut}`, `PasswordChangeIn{current_password, new_password}`
  - `api/deps.py`
    - `get_db`: 요청마다 Session을 만든다. 정상 종료하면 commit, 예외가 나면 rollback.
    - `get_clock`, `get_config`: `request.app.state.clock`, `request.app.state.config`

    - `memo`는 앞뒤 공백을 제거하고, 빈 문자열이면 None으로 저장한다.
    - 추가한 뒤 `db.flush()`.

    - 대상이 없으면 `NotFound("기록을 찾을 수 없습니다")`
    - 대상이 CANCEL이면 `Conflict("취소 기록은 취소할 수 없습니다")`
    - 이미 취소됐으면 `Conflict("이미 취소된 기록입니다")`
    - 환자가 퇴원 상태면 `Conflict("퇴원한 환자입니다")`
