# 2-4 로그인 화면 직원·보호자 선택 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버를 등록한 일반 병원 기기의 로그인 화면에서 [간호사·직원]과 [보호자 (모유 제출)]를 골라 로그인하게 한다. 보호자는 제출처 기기 토큰 없이도 조회와 제출을 할 수 있다.

**Architecture**
- **서버**
  - 마이그레이션 0003에서 `submission.station_id`와 `guardian_session.station_id`를 비어 있어도 되게 바꾼다.
  - 보호자 API에서 `X-Station-Token`을 선택 사항으로 바꾼다. 토큰 없는 세션은 "일반 기기 세션"이다.
  - 일반 기기 로그인 실패는 IP 키(`guestip:{IP}`)로 잠근다.
- **앱**
  - 로그인 화면 앞에 선택 단계를 둔다.
  - 새 경로 `GuardianGeneral`에서 2-3의 보호자 흐름을 제출처 토큰 없이 그대로 쓴다.

**Tech Stack:** 서버 FastAPI/SQLAlchemy 2/SQLite/Alembic. 앱 Kotlin/Compose/Navigation Compose. 새 라이브러리는 쓰지 않는다.

**Spec:** `docs/superpowers/specs/2026-11-13-보호자로그인선택-design.md`. 바탕은 2-3 설계 `docs/superpowers/specs/2026-11-10-2-3단계-제출처-design.md`.

**Branch:** `feature/guardian-login` (`feature/stations`에서 분기)

## Global Constraints

- 서버 규칙은 2-3a 계획의 Global Constraints를 따른다(`docs/superpowers/plans/2026-11-11-2-3a단계-제출처서버.md`).
  - 모든 트랜잭션은 `BEGIN IMMEDIATE`로 시작하고, 첫 쿼리가 쓰기 잠금을 잡는다.
  - 오류는 `DomainError`로 낸다.
  - 문구는 그대로 쓴다.
  - `uv run pytest -W error`가 모두 통과해야 한다(지금 222개).
- 앱 규칙은 2-3b 계획의 Global Constraints를 따른다(`docs/superpowers/plans/2026-11-12-2-3b단계-제출처앱.md`).
  - 문구는 strings.xml에 둔다.
  - 화면에는 아기 ID만 보인다.
  - 보호자 버튼은 64dp 이상이다.
  - 보호자 1분 무조작은 정확히 60초 경계다.
  - 보호자 토큰은 메모리에만 둔다.
  - `./gradlew testDebugUnitTest assembleDebug`가 모두 통과해야 한다(지금 301개).
- **제출처 쪽 동작은 바뀌지 않는다.** 2-3 테스트(서버·앱)는 수정 없이 통과해야 한다. 바뀌는 시그니처에 맞춘 호출부 수정은 허용한다.
- **일반 기기 세션과 제출처 세션은 섞이지 않는다.**
  - 일반 기기 세션은 제출처 토큰 없이 와야 한다.
  - 제출처 세션은 같은 제출처 토큰과 함께 와야 한다.
  - 다르면 401 "로그인이 필요합니다"
- **새 문구** (strings.xml에 그대로)
  - `login_choose_title` "누구로 들어가시나요?"
  - `login_role_staff` "간호사·직원"
  - `login_role_guardian` "보호자 (모유 제출)"
  - `guardian_general_header` "보호자 확인"
  - `login_back_to_choice` "← 처음으로"
- **서버 표시값**
  - 일반 기기 제출의 `station_name`은 "병원 기기"다.
  - 확인할 때 만드는 입고 기록 메모는 "병원 기기 제출분(제출 {n}팩)"이다.
- **새 잠금**
  - 토큰 없는 보호자 로그인 실패는 키 `guestip:{request.client.host}`로 센다. IP가 없으면 `guestip:unknown`이다.
  - 설정값은 기존 `station_lock_threshold`(20), `station_lock_window_minutes`(10), `station_lock_minutes`(10)을 쓴다.
  - 문구는 "잠시 뒤에 다시 시도해 주세요"(429)이다.

## Review Focus

1. **제출처 A에서 만든 보호자 토큰을 제출처 토큰 없이 보내거나, 반대로 일반 기기 토큰을 제출처 토큰과 함께 보냈다.** 둘 다 401이어야 한다. → Task 2 `session_mode_mismatch_is_401`
2. **같은 PC나 기기(IP)에서 여러 전화번호로 실패가 몰렸다.** 20번째에 잠기고, 다른 IP와 제출처 태블릿은 영향을 받지 않아야 한다. → Task 2 `guest_ip_lock_after_twenty`
3. **간호사 태블릿에서 보호자가 [마치기]를 누르지 않고 떠났다.** 1분 뒤 선택 화면으로 돌아가고, 다음 사람이 앞사람의 아기 ID나 재고를 볼 수 없어야 한다. → Task 3 `general_idle_returnsToChoice_andClears`
4. **보호자 화면에서 뒤로 가기를 눌렀다.** 서버 세션도 끝나고(logout 호출) 선택 화면으로 돌아가야 한다. 직원 화면으로 가면 안 된다. → Task 3 `general_back_logsOutAndReturns`
5. **데이터가 있는 DB를 0003으로 올린다.** 기존 제출(제출처 있음)과 대기 목록이 그대로 보여야 한다. → Task 1 `upgrade_0002_with_data_to_0003`

  - "서버 다시 등록" 메뉴가 보호자도 보는 선택 화면에서 열리던 문제: 직원 로그인 화면에만 둔다.
- 최종 검토에서 고친 것
  - **로그인 중 "← 처음으로":** 직원 로그인이 진행되는 동안 누를 수 있어, 로그인이 늦게 끝나면 보호자 앞에서 직원 화면이 열릴 수 있었다. 로그인 중에는 버튼을 막는다.
  - **입력 없는 보호자 화면:** 아무것도 입력하지 않으면 선택 화면으로 돌아가지 않았다. 화면에 들어오면 1분 타이머를 시작한다.
  - **제출처 이름 "병원 기기" 금지:** 일반 기기 제출분과 헷갈리지 않게 한다.
  - 상위 설계 11장 번호, 서버 README 보호자 로그인 설명
- 진행 중 결정
